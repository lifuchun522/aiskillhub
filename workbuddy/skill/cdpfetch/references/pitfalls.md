# 踩坑清单

> 这个技能里最该持续更新的不是「正确做法」，而是「曾经错在哪」。前者是常识，后者是经验。
> 每条都对应一次真实返工，标注发现日期。当作**可能有效的提示**而非保证。

## P0 — 会让结论失真的

### P0-1　把「页面文字」当成一手事实　`2026-10-08`

第三方站点大量转载**已下架**的旧定价。实战：多个二手页面仍在写某产品
「Professional $25/月」，而官网定价页只剩 Basic / Enterprise 两档。

**对策**：定价、协议、配额这类会变的数值，**必须回官网一手页**（定价页 / 文档 / 仓库）。
发现一手与二手冲突时，把冲突写进洞察，不要静默采信任一方。

### P0-2　CDP 通道的 `status: 200` 是假的　`2026-10-08`

CDP 协议**不回传 HTTP 响应码**。`cdp_fetch.mjs` 里的 `status` 只能表示「导航请求被接受」。

**实测证据**：对一个不可解析的域名发起抓取，CDP 通道给出
`status: 200`、`title: 该域名`、`text_len: 141`——正文是浏览器的「无法访问此网站」错误页。
只按 `status == 200` 判断，就会把一次失败记成一次成功。

**对策**：
- `cdp_fetch.mjs` 已内建错误页识别（`final_url` 以 `chrome-error://` 开头、或存在 `#main-frame-error`），命中即 `ok=false`。
- 人工复核的第二道判据是 `text_len` 与 `title`：`text_len` 异常小基本可以判定没抓到正文。
- 存证里必须记 `channel`，报告里说清数据来自哪条通道。

### P0-3　用「今天」代替抓取时间　`2026-10-08`

标注「数据截至今天」等于没标——无法复核、无法判断时效。

**对策**：顶部横幅写**抓取窗口**（`_manifest.json` 里 `fetched_at` 的最小值 → 最大值），
证据表逐行写该条的精确时间。`fetched_at` 必须带时区（`+08:00`），跨时区协作才不会误读。

### P0-4　静默剔除失败项　`2026-10-08`

19 个目标里 2 个抓取失败就只展示 17 个——这等于**制造样本偏差**，
而且掩盖了「某来源不可达」这个本身就是结论的信息。

**对策**：失败项进证据表并标注失败原因。整批失败率过高时应先修抓取，而不是先出报告。

## P1 — 会让交付物不可用的

### P1-1　单文件看板被外链「污染」　`2026-10-08`

用 CDN 引字体 / Chart.js / 图片，本地双击打开可能全白或样式尽失（离线、内网、预览器拦截都会中招）。

**对策**：交付前跑 `verify_dashboard.py`，`externalRefs` 必须为 0。
图表用内联 SVG 或纯 CSS 实现，别引图表库。

### P1-2　锚点导航与自定义滚动打架　`2026-10-08`

`<a href="#sec">` 会写 URL hash、触发浏览器默认跳转，和 `scrollIntoView({behavior:'smooth'})` 叠加后位置错乱。

**对策**：导航一律 `<button type="button" data-scroll="sec-id">`，
点击后 `document.getElementById(id).scrollIntoView({behavior:'smooth'})`。

### P1-3　漏滚动导致正文残缺　`2026-10-08`

懒加载页面（长官网、文档站）不滚动到底，下半部分内容根本不进 DOM，
`innerText` 拿到的是一份**看似正常但不完整**的文本——最危险的一类错误。

**对策**：`--scroll 3`（默认）触发懒加载。判断抓取是否完整，看 `text_len` 是否
与其他同类页面量级相当；异常偏小就加滚动次数重抓。

### P1-4　Agent 没有 HTTP 状态线索时误判成功　`2026-10-08`

页面返回「内容不存在 / 页面不见了」不一定是真不存在，也可能是 URL 缺必要参数或触发反爬。

**对策**：URL 必须**原样保留完整参数**（含 token、session 等）传入；
站点内交互得到的链接天然带上下文，比手工拼 URL 可靠。

## P2 — 影响观感与可维护性的

### P1-5　验证器自己的假阳性，比不验证更危险　`2026-10-08`

把 `verify_dashboard.py` 的初版直接拿去验一份**已被人工确认合格**的看板，报出 2 项 FAIL——
**两项都是验证器的错，看板没问题**：

| 误报 | 错在哪 |
|---|---|
| 「按钮导航未生效」 | 判据是「点击**首个**按钮后 `scrollY > 0`」。首个按钮指向页首区块 `#sec-overview`，点完 `scrollY` 本就该是 0 |
| 「中英切换未生效」 | 取样元素是表头第二列，那是**产品名**（`AgentScope`），中英两侧本来就相同 |

还有一类是纯代码错误：拿布尔字面量 `True` 和一段描述性文本做相等比较，
结果「已通过」被渲染成 FAIL。

**为什么这比不验证更危险**：假阳性会让人去改本来正确的东西，或者干脆从此不信验证结果——
两种结局都让验证失去意义。

**对策**：
- 断言的判据要**锚定到被测对象的语义**：导航要逐按钮验证「是否真滚到目标区块」，
  而不是「`scrollY` 是否大于 0」；语言切换要验**整页正文指纹**是否变化、能否切回还原，
  而不是某个可能中英同形的取样元素。
- **"判定 + 说明" 与 "期望值 vs 实测值" 是两种检查**，别混用同一个比较函数（会撞上类型比较）。
- 验证器写完后，**必须拿一个「故意做坏的样本」反向跑一遍**，确认它真的会报红。
  只验证「能报绿」的验证器，等于没验证。

### P2-1　雷达图轴标签压在图元上　`2026-10-08`

标签锚点全用 `middle` 时，左右两侧的标签会横跨到图形上。

**对策**：按标签点相对圆心的水平位置决定 `text-anchor`：
`|lx - cx| < 6` → `middle`，`lx > cx` → `start`，否则 → `end`。

### P2-2　卡片高度参差　`2026-10-08`

描述文案长短不一，同一行卡片高度不齐，网格看起来像坏了。

**对策**：给描述块一个 `min-height`，并统一「事实行」的行数。
长文本统一截断并保留 title 提示，不要靠 `flex: 1` 硬撑。

### P2-3　目标 key 重复导致落盘互相覆盖　`2026-10-08`

同一批抓取里两个目标用了相同 key，后者覆盖前者，且**不报错**——
报告里少一个来源而你毫无察觉。

**对策**：两个脚本都会在加载清单时**主动检测 key 重复并直接退出**。
key 带来源前缀（`vendorA_pricing` 而非 `pricing`）。

### P2-4　Node 版本不够导致 WebSocket 未定义　`2026-10-08`

`cdp_fetch.mjs` 依赖 Node 22+ 的原生 `WebSocket`。Node 18 下报
`WebSocket is not defined`，容易误判成 CDP 端点有问题。

**对策**：先 `node -v` 确认 ≥ 22。低版本用 Playwright 通道。

### P2-5　中英切换用运行时翻译　`2026-10-08`

在 `toggleLang()` 里做字符串替换或调翻译，切换后可视化重渲染、状态丢失、译文不可控。

**对策**：**双侧编译**——数据里每个文案存 `{zh, en}`，切换只改 `LANG` 后整体重渲染；
同步更新 `document.documentElement.lang`。

### P2-6　截图靠人眼单点确认　`2026-10-08`

只截一张全页图，缩略后根本看不清 12px 的文字是否溢出。

**对策**：按区块 `elementHandle.screenshot()` 单独截，并用 `device_scale_factor=2`；
验证脚本同时给**确定性计数**（DOM 数量、外链数、控制台错误数），
截图只作补充证据，不作唯一依据。
