# eli5a · ELI5 微信图文

把一件刚发生的技术事件，写成**约 500 字、上限 1000 字**、配 3-6 张图、能直接粘进公众号源码模式的图文。

**风格底色**：有见识的普通人在认真聊一件打动他的事。不是导师讲课，不是品牌发稿。

**写法核心**：ELI5。每个抽象论点必须落回案例的一个具体部件或场景，不给悬空的结论。

**篇幅纪律**：说清结论和论点即可，不铺陈。**目标 500 字，硬上限 1000**（页面文字，图注不计入页面）。读者要能一句话带走。

## 交付物定义（验收标准，缺一不算完成）

1. 页面正文 **目标 500 个中文字、上限 1000**（用 `[\u4e00-\u9fff]` 正则计数，不能靠感觉）
2. 一个**单文件 HTML**：图片全部 base64 内联，零外链
3. 版式：单行爆炸标题、编号递进章节、单栏 677px 居中、衬线字体、行高 1.8、天蓝纸质背景、章节虚线分隔
4. 配图 **3-6 张**，其中「形象说明」与「逻辑推演」两处必须有
5. 同时另存**独立 JPG** 到工作目录（微信正文不接受 base64，需后台上传替换）
6. 微信兼容红线全部满足（见 `references/wechat-compat.md`）

## 标题规则

- **单行，禁止 `<br>` 换行**。一行读完。
- **≤12 个中文字**，8-11 字最佳。
- **爆炸点 = 反常识 / 反差 / 数字冲突**，让人第一眼想点，且能口头复述传播。
- 常用结构：`数字+反常识`（两万块，机器人真发货了）、`断言+反差`（车能飞，你买的那台不能）。
- 副标题一行，只补「用大白话讲清什么」，≤20 字，不抢主标题。

## 章节规则

章节用**编号徽章 + 论点式短名**，左对齐，上行虚线。禁止「◇ 叁 · 白话讲讲那三座大山 ◇」这类又长又散的样式。

```html
<div style="margin:34px 0 18px;border-top:1px dashed #8fb9d6;padding-top:16px;"><span style="display:inline-block;background:#0b3d63;color:#ffffff;font-size:12px;font-weight:700;padding:2px 9px;letter-spacing:1px;vertical-align:middle;">01</span><span style="display:inline-block;margin-left:8px;font-size:19px;font-weight:700;color:#0b3d63;letter-spacing:1px;vertical-align:middle;">章节名</span></div>
```

章节名四条硬约束：

1. **是论点，不是名词短语**。写「交付之后，比的不一样了」，不写「关于交付」。
2. **≤10 字**，不加语气词，不加「讲讲」「聊聊」「白话讲讲」这类口水前缀。
3. **必须递进**：01 是什么 → 02 为什么/变了什么 → 03 卡在哪 → 04 一句话带走。
4. 全文 **3-4 幕**，最后一幕固定叫「一句话带走」。

## 配图与图注规则

- **页面里不放图注 div**，图片块只有 `<img>`。
- 图注**画进图片底部深蓝条的左侧**，品牌水印「资深架构师 李福春」在**右侧**，两者同一行、同一条底带。
- **禁止「图一 / 图二」编号**。
- 图注 ≤12 字，写画面本身，不重复正文。

```html
<div style="margin:22px 0;text-align:center;"><img src="{{IMG1}}" style="display:block;width:100%;border:1px solid #8fb9d6;"></div>
```

## 结尾规则

- **删除任何品牌口号行**（如「把复杂系统，设计成简单可依赖的产品。」）。结尾不放签名式口号。
- 最后一幕「一句话带走」：一行加粗居中金句（19px），是全文唯一要读者记住的句子。
- 紧跟一句行动号召，回扣开头的场景或意象。

## 流程

### 步骤 1 · 核实素材

联网检索，落地一张**事实清单**：时间、地点、主体、价格/参数、关键人物原话、第三方机构数据、反面声音。禁止凭记忆写数据，每条数据都要能追到来源。

### 步骤 2 · 定角度与结构

从「现象 → 原因 → 卡点 → 带走」四幕起步。每幕一个论点，论点后面必须跟案例里的具体部件或场景。

常用角度（选一个，不要全上）：

- 反差型 · 最炸的画面 ≠ 你能买到的东西
- 原理型 · 用一句大白话比喻讲清技术，再补硬数据
- 现实型 · 技术成立了，但制约在成本/法规/供应链
- 时间型 · 从承诺到兑现之间的落差

### 步骤 3 · 写正文

- 开篇：具体场景或反常识设问做钩子，禁止宏大叙事开场
- 短句推进，一句话能独立成段就独立成段
- 金句单独成段并加粗
- 知识是「聊着聊着顺手掏出来」的，不是「下面我来科普一下」
- **先写 1000 字，再砍到 500**。砍的是解释和铺垫，不是数据和金句

**ELI5 三段式对照**（通俗与严谨都写，不用按钮切换，直接上下并列排版）：

- 一个生活比喻（气球、吸尘器、便利店、后厨）
- 一句工程说法（带真实参数）
- 一句读者能带走的判断

### 步骤 4 · 生成配图

- 场景图用 ImageGen，**图内绝不放中文**（100% 乱码）
- 示意图/含中文标注的用 Pillow + 中文字体直排，画布底部留 ≥100px
- 全部打品牌水印并覆盖平台「AI生成／WORKBUDDY」水印（`build.py` 自动做）
- 每章最多一张图，图必须服务该章论点，不做装饰性配图

### 步骤 5 · 构建单文件 HTML

用 `templates/wechat-article.html` 作骨架，占位符 `{{IMG1}}`…`{{IMGn}}`。然后跑 `scripts/build.py` 完成水印、图注、压缩、base64 内联与校验。

```bash
python scripts/build.py --src draft.html --out 成稿.html --img img1.jpg img2.jpg --cap "图注1" "图注2"
```

### 步骤 6 · 校验（必须实跑，不能推断）

- 字数：`[\u4e00-\u9fff]` 计数，页面 ≤1000、目标 ≤600
- 标签开闭、img 数、`http` 外链布尔、HTML 实体残留、`<br>` 残留
- 「图一/图二」编号残留 = 0；结尾口号行残留 = False
- 微信兼容红线：无 JS、无 `<style>` 块、无 class/id、无表单元素、无外链
- Playwright 实渲染：页高、正文栏宽、逐图截图确认中文无乱码、标题单行不折行

### 步骤 7 · 交付闸门（D12，强制）

**在决定发送的那一刻才加载 `delivery-no-pseudoblock`**，作为发送前最后一道拦截。不得在回合开头加载它当合规盖章；加载时机早于实质工作 = 闸门失效。交付消息内必须贴 D1-D12 逐项闸门快照，每项写实际核对了什么。
