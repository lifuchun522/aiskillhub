# 01 · 工作流

两条路径，共用同一份模板与同一套渲染规则：

| 路径 | 入口 | 适合 | 产物 |
|---|---|---|---|
| **A 表单路径（快）** | 浏览器打开 `assets/form.html` | 手上只有零散材料，想边填边看效果；不装 Python 环境 | 一个自包含 `index.html`（图片内联） |
| **B 命令行路径（稳）** | `python scripts/build_portfolio.py content.json` | 有素材目录 / 要 PNG8 量化压体积 / 要进 CI | `index.html`（默认内嵌）或 `index.html` + `img/`（配了 `paths.external`） |
| **B′ 命令行 + 图片外置** | 同上，`"paths": {"external": "img"}` | 要单独换图 / 要进 CDN / 要页面从几 MB 瘦到几十 KB | 68 KB 的 `index.html` + `img/<项目>/<名>.<ext>` |

两条路径产出的页面**结构等价**（`tests/test_browser.py` 里逐字比对），差别只在图片编码强度。
B′ 不是第三条路径，只是 B 的一个开关：渲染规则完全相同，只是图不再塞进 HTML。

---

## 路径 A：表单路径

```bash
# 直接双击打开即可（file:// 下也完全可用）
assets/form.html
```

1. **「载入示例」** —— 先看一眼成品长什么样，再决定自己怎么填。
2. 按九个区块填：基础信息 / 首屏数据条 / 首屏名片 / 第一人称自述 / 核心能力支柱 /
   技术栈分组 / 工作经历 / 教育背景·认证·主页 / 我的项目。
   - 右上角常驻**填写进度条**与**检查面板**：缺什么、哪条太虚、体积有没有超，都列出来。
   - 数据条、支柱、分组、经历、认证、主页、项目都可以增删；项目卡里还能加多张补充架构图。
3. **「导出 JSON」** —— 存一份 `xxx-content.json`，下次「导入 JSON」接着改（不丢信息）。
   表单也会自动把「文字部分」存进浏览器 localStorage 做草稿，图片不会进草稿。
4. **「生成作品集」** —— 当场在弹层里预览，然后「另存 HTML」。

> 表单里所有图片都会变成内联 data URI。图片选择后立即按用途压缩：
> 名片 / 二维码**不缩放不重压**，手绘架构图 1440px、技术分层图 1280px、证书 620px。
> 内嵌总量超过 5MB 时检查面板会告警 —— 这时候应该改走路径 B（能做 PNG8 量化）。

### 图片不能做的两件事

- 浏览器读不到本机磁盘路径。导入「命令行格式」的 `content.json` 时，图片槽会显示
  「磁盘路径，需重新选择」，并在面板里列出是哪几张 —— **不会静默丢图**。
- 浏览器里做不了 PNG8 调色板量化。要压体积只能走路径 B。

## 路径 B：命令行路径

```
① 准备素材        images/           架构图、证书、二维码、名片
② 写 content.json 字段规格见 03-content-schema.md
③ 构建            python scripts/build_portfolio.py content.json --stats
④ 自检            python scripts/verify.py "<out>/index.html" --expect … --last-section projects
⑤ 打包            python scripts/package.py "<out>"
⑥ 交付前闸门      加载 delivery-no-pseudoblock，实跑 D1–D12
```

### 图片编码策略

| 用途 | 目标宽度 | 格式 | 说明 |
|---|---|---|---|
| 首屏名片 | 不缩放 | 原格式 | 保留原始字节；卡面小字靠点开放大看 |
| 手绘架构图 | 1440 | JPEG q80 | 照片类 / 手绘类素材 |
| 技术分层架构图 | 不缩放 | **PNG8 量化** | 线条 + 大色块，量化后肉眼无损、体积省 50%+ |
| 证书 | 620 | JPEG q84 | 只做缩略展示 |
| 二维码 | 不缩放 | **PNG 无损** | JPEG 会破坏定位图案，直接扫不出来 |

**直通（passthrough）**：无需缩放且源格式 == 目标格式时复用源字节，不做重编码 ——
避免 JPEG 二次压缩的画质累积损失。源格式用 PIL 探测（`im.format`），不信任扩展名。

### 归档

`images[key].archive` 决定这张图的「原分辨率」副本落到哪里（如
`diagrams/技术分层版/01-AgentX-技术分层架构图.png`），方便拖进 PPT / 文档复用。
归档的是**无损原图**，与内嵌那份（可能已量化）不同。

## 页面叙事顺序（由模板固定）

```
Hero（一行 tagline + 满宽名片）→ 首屏数据条 → ABOUT ME 自述
  01 / CAPABILITY   核心能力（2–4 条支柱）
  02 / TECH STACK   技术栈分组
  03 / CAREER       工作经历（按时间由近及远）
  04 / CREDENTIAL   教育背景 · 专业认证 · 个人主页
  05 / MY PROJECTS  我的项目（一个项目一节）
```

项目放最后：前面先把能力、技术栈、履历交代清楚，再用项目做实证。
章节序号由 DOM 顺序自动生成，挪区块不必手改编号。

## 五端渲染检查表

`verify.py` 用真实 UA 起 5 个 profile，每端四件事：

| profile | 视口 | UA | 无横向溢出 | 关键区块不超宽 | 正文字号 ≥12px | 名片在首屏 |
|---|---|---|---|---|---|---|
| 桌面 Chrome | 1440×900 | Chrome 126 | ✓ | ✓ | — | ✓ |
| 平板 | 820×1100 | WeChat iOS | ✓ | ✓ | ✓ | ✓ |
| iPhone 微信 | 390×844 | MicroMessenger 8.0.49 | ✓ | ✓ | ✓ | ✓ |
| Android 微信 | 360×780 | XWEB 1160065 | ✓ | ✓ | ✓ | ✓ |
| iPhone 企业微信 | 320×568 | wxwork 4.1.26 | ✓ | ✓ | ✓ | ✓ |

320 / 360 两档必须单独跑 —— 2px 的横向溢出只在窄屏暴露，在桌面上完全看不出来，
但真机上就是「整页能左右晃」。
