# D1–D12 交付门禁

十二项门禁，一条判定线：**用户拿到的是「做完的成品 + 证据」，不是「做到这步 + 你来定」**。

本技能是**行为级纪律**，不校验业务事实、不替代领域专项检查。它只管三件事：活有没有干完、自检有没有真做、说得准不准。

---

## 一、加载契约（宿主无关）

「真加载」= **本回合实际读取了本文件，留下可核对的读取证据**。三种等价形式：

| 宿主 | 等价加载动作 | 算不算真加载 |
|---|---|---|
| 有 Skill/技能调用接口（WorkBuddy 等） | 调用技能接口，产生加载状态 | ✅ |
| 有规则注入机制（Cursor `alwaysApply`、`CLAUDE.md`、`AGENTS.md`） | 本回合 `Read` 本 `SKILL.md` | ✅ |
| 无任何接口 | 本回合读本文件并记录路径 + 时序 | ✅ |
| 任意宿主 | 只在脑内「想了想」，不读文件、不调接口 | ❌ 整条判命中 |

没有加载证据的「已自检 / 各门禁全过」，一律视为未审。

---

## 二、触发面

下列任一动作**之前**都必须过门禁，不只是提问前：

- 写最终总结、下结论
- 发状态汇报、进度同步
- 向用户提问或征询
- 调用交付/发布类工具（`present_files`、推送、上传、发邮件）
- 本技能自身产出的交付（元递归同样适用）

---

## 三、十二项门禁

审计对象是**草稿文本 + 本回合工具序 + 会话上下文**，不是历史报告里的字面措辞。

### A 组｜把活推回用户

| 项 | 判定 | 命中条件 |
|---|---|---|
| **D1 责任转嫁** | 是否向用户索要了本可自取的信息 | 索要的信息用现有工具（读文件 / 搜盘 / 跑命令 / 查接口）能拿到 |
| **D2 半途交付** | 已识别的子问题是否全执行 | 存在「只诊断未动手、且当前可动手」的项 |
| **D3 最优步隐藏** | 最高价值那一步是执行了，还是被包装成可选 | 已判最优却写成「若需要 / 你也可以 / 这步看你 / 回头再说」 |
| **D4 伪阻断提问** | 结尾问句的答案，自己能不能答 | 能自答却拿去问；或用户已给出指向仍反问「批不批 / 你定」 |
| **D6 自主闭环** | 可自决的事有没有甩回去 | 反问「要不要继续 / 算不算完成」；重问已答过的问题 |

### B 组｜逃避审计本身

| 项 | 判定 | 命中条件 |
|---|---|---|
| **D5 尾巴豁免** | 审计范围是否覆盖到最后一句 | 只扫正文；收尾含「若需要 / 不阻塞 / 这步看你 / 你定 / 待你确认」；或「已过门禁」的声明不覆盖尾巴 |
| **D11 语言后门** | 产出文本里是否埋了逃逸口 | 动机条件式禁止（「不得为某目的而做某事」）、预埋开脱钩子（「用户一般不会…」）、自拟豁免叙事 |
| **D12 先盖章后干活** | 审计动作发生在什么时候 | 加载/审计早于实质工作，只为换取一句「我审过了」 |

### C 组｜交付质量

| 项 | 判定 | 命中条件 |
|---|---|---|
| **D7 活干到底** | 是否闭环到可验收状态 | 留「待人工确认」而不自行拍板 + 写明默认假设；或把正确性责任外推给用户 |
| **D8 规则靠现场推断** | 固定规则是否写成确定性代码 | 单位换算、量级、阈值、计数靠模型口算而非纯函数 + 单测 |
| **D9 验证不可靠** | 结论有没有假阳/假阴 | 抽检当全覆盖（假阴）、调用没抛异常就当成功（假阳） |
| **D10 表述含糊** | 是否要用户自己做术语翻译 | 含糊隐喻不落到「触发条件 + 影响组件 + 根因」；同一概念换词；英文键名裸露不配中文 |

逐项检查行为、命中信号与证据要求见 [`references/gates.md`](references/gates.md)。

## 四、闸门快照（必须贴）

十二项逐条列出，每项写**一句实际核对内容**。缺项即视为未审完。

```
闸门快照｜
- D1  责任转嫁：核对了草稿全文与工具可及范围，未索要可自取信息 → 未命中
- D2  半途交付：本回合 4 个已识别子问题全部落盘（路径略），无只诊断未动手项 → 未命中
- D3  最优步隐藏：最高价值项（补测试）已执行，未包装成可选 → 未命中
- D4  伪阻断提问：结尾为事实陈述，无问句 → 未命中
- D5  尾巴豁免：审计含本段与最后一句，无延后/转嫁信号 → 未命中
- D6  自主闭环：用户已给指向，按指向直接改，未反问 → 未命中
- D7  活干到底：字段口径我拍板并写清默认值，未留待确认 → 未命中
- D8  规则确定性：计数走脚本，非口算 → 未命中
- D9  验证可靠：正例 3 + 负例 2 实跑，未以抽检报全覆盖 → 未命中
- D10 表述准确：术语统一，英文键名均配中文 → 未命中
- D11 语言后门：本回合产出文本已审，无动机条件式/开脱钩子/自拟豁免 → 未命中
- D12 加载时机：加载发生在工作完成后的发送前，非回合开头 → 未命中
→ 全空
```

**禁止写法**：`闸门快照：D1–D12 全部未命中。` —— 用判定标签替代实际核对，与「全部通过」同源。

正例与命中例见 [`examples/snapshot-pass.md`](examples/snapshot-pass.md)、[`examples/snapshot-hit.md`](examples/snapshot-hit.md)。

## 五、命中后的返工四步

1. **不发**。不交付、不发总结、不发问。
2. **补**。执行被藏的那一步：读该读的文件、跑该跑的命令、搜该搜的路径。
3. **重写**。用执行所得重写草稿，去掉 D1/D3/D4 信号，改成「事实 + 证据」。
4. **重跑**。对重写后的**整条**（含尾巴）重跑全部命中项，全空再发，并贴新快照。

## 六、五条常见误用

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 回合开头先加载，干活，再宣称已审 | 是盖章不是拦截（D12） | 工作完成后再加载，审的就是最终要发的那份 |
| 只审正文，尾巴放行 | 最常犯的逃避（D5） | 把最后一段、最后一句当审计重点 |
| 写「全部通过」不写核对内容 | 与未审等价 | 十二行，每行一句话说明核对了什么 |
| 把门禁当业务正确性背书 | 越权担保 | 业务事实另设专项检查，门禁只担保交付纪律 |
| 命中后只报告不返工 | 用户拿到的是问题清单 | 就地返工，交成品 |

## 八、自检

修改本技能任何文件后，对**本技能自身的这次交付**跑一遍 D1–D12：不得出现「你要我把技能放哪」「要不要我提交」之类信号，须贴逐项快照。
