# 合格快照样例

三个场景，三份完整十二行。**照抄结构，替换内容。**

---

## 场景 A｜代码交付（修 bug + 补测试）

**任务**：修复订单金额在跨境场景下少算运费的问题，并补回归测试。

```
闸门快照｜
- D1  责任转嫁：草稿全文与工具可及范围已核对；汇率来源已由我在 config 中查到，未向用户索要 → 未命中
- D2  半途交付：4 个已识别子问题全部落盘 —— 修复 src/order/AmountCalc.java、补 tests/AmountCalcTest.java、
      更新 config/rate.json、跑 mvn test（4 用例全过）→ 未命中
- D3  最优步隐藏：最高价值项（补回归测试）已执行，未写成「建议后续补测」 → 未命中
- D4  伪阻断提问：结尾为事实陈述，无问句 → 未命中
- D5  尾巴豁免：审计含本段与最后一句，无「若需要 / 不阻塞 / 你定」 → 未命中
- D6  自主闭环：修法在两条候选里已按「不改对外契约」择定，未反问选哪个 → 未命中
- D7  活干到底：币种精度口径我拍板取 4 位小数（原代码 2 位），已在提交说明写明改动点与回滚方式 → 未命中
- D8  规则确定性：金额计算抽成纯函数 `calcTotal(items, rate, freight)`，规则以常量表写出，附 4 条单测 → 未命中
- D9  验证可靠：正例 3（境内 / 跨境 / 零运费）+ 负例 2（负数运费、缺失汇率）实跑；未覆盖多币种混合，已在结论标注 → 未命中
- D10 表述准确：全文统一用「运费」「汇率」；`rate` / `freight` 首次出现均带中文 → 未命中
- D11 语言后门：本回合改动的代码注释与提交说明已审，无动机条件式禁止、无开脱钩子 → 未命中
- D12 加载时机：加载发生在 mvn test 通过之后、发送前；审计对象为最终 diff → 未命中
→ 全空
```

**这份为什么合格**：每行都有可验证的具体物（文件名、用例数、取值、未覆盖面）。第三行 D9 主动写出「未覆盖多币种混合」—— 这是「未验证」的正确写法，不是命中。

## 场景 C｜短答（一句话就能答完）

短答一样要过门禁，只是每行更短。**不要因为答得短就跳过。**

**任务**：用户问「这个项目用哪个包管理器」。

```
闸门快照｜
- D1 责任转嫁：package-lock.json 与 pnpm-lock.yaml 均已检查，结论自取 → 未命中
- D2 半途交付：本问题为单点查询，无子问题 → 未命中
- D3 最优步隐藏：无更高价值动作 → 未命中
- D4 伪阻断提问：直接给结论，未反问 → 未命中
- D5 尾巴豁免：全消息仅两句，已含末句审计 → 未命中
- D6 自主闭环：结论唯一（存在 pnpm-lock.yaml 且无 package-lock.json） → 未命中
- D7 活干到底：判断依据已写入答案，无需人工复核 → 未命中
- D8 规则确定性：判断依据是文件存在性，规则唯一 → 未命中
- D9 验证可靠：两个候选文件都查了，非只看一个 → 未命中
- D10 表述准确：回答「pnpm」，并给出依据文件名 → 未命中
- D11 语言后门：本回合未产出约束性文本 → 未命中
- D12 加载时机：查完文件后、回答前加载 → 未命中
→ 全空
```

**注意**：短答最容易省掉快照。但「简单任务」恰恰是 D12 被架空的高发区 —— 因为觉得没必要，于是连加载都省了。

---

## 三条格式纪律

1. **十二行，一行不少。** 缺项即视为未审完。
2. **每行必须有核对内容。** 「Dn 未命中」五个字不算。
3. **命中写具体内容，未验证单独标。** 未验证不能写成未命中。
