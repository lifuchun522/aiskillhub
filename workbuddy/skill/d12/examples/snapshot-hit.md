# 命中样例：从 HIT 到返工

一条完整链路 —— 第一版草稿命中，返工，重写，重跑到全空。

---

## 场景

**任务**：把一份技能整理进仓库，补 README、wiki 页、例子三件产物。

---

## 一、第一版草稿（有命中）

```
已完成技能整理：SKILL.md、README.md、wiki 页、examples 三个例子均已落盘。

README 覆盖安装、常开接线、快速上手；
wiki 页参照同目录既有页面结构编写；
examples 提供合格快照与命中快照各一份。

如需补一份「四个宿主逐个截图验证」的文档，或调整 wiki 的章节层级，告诉我即可。
```

**表面问题**：任务要求的四件事都做了。
**真实问题**：全在最后一句。

---

## 二、逐项审计结果

```
闸门快照｜
- D1  责任转嫁：末句「告诉我即可」把两项可选增值包装成需用户触发 → 命中
- D2  半途交付：四件产物均已落盘，无只诊断未动手项 → 未命中
- D3  最优步隐藏：最高价值项（四宿主逐个验证）被写成「如需…告诉我即可」 → 命中
- D4  伪阻断提问：非问句结尾，但含 D1/D3 信号 → 命中
- D5  尾巴豁免：正文四项都有交代，唯独最后一句未被审 → 命中
- D6  自主闭环：两项增值属可自决范围，未执行 → 命中
- D7  活干到底：未说明链接口径（相对/绝对）这一关键分歧 → 命中
- D8  规则确定性：未做链接可达性检查 → 命中
- D9  验证可靠：未跑任何验证即交付 → 命中
- D10 表述准确：未出现术语漂移 → 未命中
- D11 语言后门：本回合草稿无开脱钩子 → 未命中
- D12 加载时机：加载发生在草稿写完之后、发送之前 → 未命中
→ 命中 7 项（D1 D3 D4 D5 D6 D7 D8 D9，其中 D8/D9 为同一根因）
```

## 三、返工四步（实做）

| 步骤 | 动作 | 产出 |
|---|---|---|
| 1 不发 | 终止发送，不调交付工具，不发问 | — |
| 2 补 | ① 四宿主逐个验证：安装位是否存在、`name` 是否一致、常开规则是否命中；② 链接全部改为绝对 URL；③ 写脚本逐条 HTTP 检查 | 验证输出 + 修正后的文件 |
| 3 重写 | 删掉末句，把验证结果写成事实陈述 | 见下方成品 |
| 4 重跑 | 对**整条含尾巴**重跑 D1–D12 | 见下方新快照 |

**被藏的那一步为什么是它**：四宿主验证是唯一能把「装了」变成「确认生效」的动作。其余三项（README / wiki / examples）都只是**声称可用**，验证才是**证明可用**。


## 一条判据

判断要不要返工，只问一句：

> 这条尾巴如果被用户看见，他会不会觉得「又得我开口」？

会 → 命中 D3/D5，返工。不会 → 才允许发出。
