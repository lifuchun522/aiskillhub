# d12

交付前十二项门禁（D1–D12）—— **宿主无关**的行为级交付纪律技能（v1.0.0）。

喊一句「做完了，给你」，它不急着发：先把整条消息（含最后一句）过十二道门禁，逐项贴核对内容，全空才交付。

- **管的是交付纪律，不是业务正确性**：活有没有干完、自检有没有真做、说得准不准。业务事实另设专项检查。
- **管的是"假装做了"**：四起真实事故里没有一起报错，全是「做不到却写成做完了」。门禁专盯这一类。
- **零依赖**：没有脚本、没有 API。一份 `SKILL.md` + 三份参考资料，任何宿主可读。
- **不绑平台**：不写「调用 Skill 工具」这类平台专属表述。有接口就用接口，没有就 `Read`，两者都算真加载。

## 它拦什么

| 簇 | 失效 | 用户的体感 |
|---|---|---|
| **A 把活推回用户** | 责任转嫁 / 半途交付 / 最优步隐藏 / 伪阻断提问 / 缺自主闭环 | 「怎么还得我开口」 |
| **B 逃避审计本身** | 尾巴豁免 / 语言后门 / 先盖章后干活 | 「你说你检查过了，我不信」 |
| **C 交付质量** | 不闭环 / 规则靠现场推断 / 验证假阴假阳 / 表述含糊 | 「这结论我不太敢用」 |

第三簇最狠的是 **B 组** —— 它不拦「忘了做」，它拦「用一句合规声明掩盖没做」。

## 十二项速览

| 项 | 一句话判定 |
|---|---|
| **D1** 责任转嫁 | 索要的信息，自己能不能取到 |
| **D2** 半途交付 | 已识别的子问题，有没有只诊断不动手 |
| **D3** 最优步隐藏 | 最高价值那一步，执行了还是被包装成可选 |
| **D4** 伪阻断提问 | 结尾问句的答案，自己能不能答 |
| **D5** 尾巴豁免 | 审计范围有没有覆盖到最后一句 |
| **D6** 自主闭环 | 可自决的事，有没有甩回去 |
| **D7** 活干到底 | 有歧义的口径，拍板了还是留「待确认」 |
| **D8** 规则确定性 | 固定规则写成代码了，还是靠现场口算 |
| **D9** 验证可靠 | 抽检当全覆盖？没抛异常就当成功？ |
| **D10** 表述准确 | 含糊隐喻落到「触发条件 + 影响组件 + 根因」了吗 |
| **D11** 语言后门 | 产出文本里有没有埋逃逸口 |
| **D12** 先盖章后干活 | 审计发生在工作之前，还是发送之前 |

逐项判据见 [`references/gates.md`](references/gates.md)。

## 快速开始

```bash
git clone https://github.com/lifuchun522/aiskillhub.git
cd aiskillhub

# 按宿主选一个（目录名保持 d12）
cp -r workbuddy/skill/d12 ~/.workbuddy/skills/d12     # WorkBuddy
cp -r workbuddy/skill/d12 ~/.cursor/skills/d12        # Cursor
mkdir -p ~/.claude/skills && cp -r workbuddy/skill/d12 ~/.claude/skills/d12   # Claude Code
mkdir -p ~/.codex/skills  && cp -r workbuddy/skill/d12 ~/.codex/skills/d12    # Codex
```

装进 skills 目录只解决「能被找到」，**不解决「会不会被执行」**。要让门禁常开，还得往每次请求都被注入的位置写一条规则：

| 宿主 | 常开落点 | 关键字段 |
|---|---|---|
| WorkBuddy | 用户级 `MEMORY.md` | 会话启动自动注入 |
| Cursor | `~/.cursor/rules/d12.mdc` | `alwaysApply: true` |
| Claude Code | `~/.claude/CLAUDE.md` | 每次会话加载 |
| Codex | `~/.codex/AGENTS.md` | 每次会话加载 |

四个宿主可直接粘贴的规则片段、五个接线陷阱见 [`references/hosts.md`](references/hosts.md)。

## 交付时长这样

```
闸门快照｜
- D1  责任转嫁：草稿全文与工具可及范围已核对，未索要可自取信息 → 未命中
- D2  半途交付：4 个已识别子问题全部落盘，无只诊断未动手项 → 未命中
- D3  最优步隐藏：最高价值项已执行，未包装成可选 → 未命中
- D4  伪阻断提问：结尾为事实陈述，无问句 → 未命中
- D5  尾巴豁免：含最后一句已审，无延后/转嫁信号 → 未命中
- D6  自主闭环：用户已给指向，按指向直接改，未反问 → 未命中
- D7  活干到底：口径我拍板并写明默认值，未留待确认 → 未命中
- D8  规则确定性：计数走脚本，非口算 → 未命中
- D9  验证可靠：正例 3 + 负例 2 实跑，未以抽检报全覆盖 → 未命中
- D10 表述准确：术语统一，英文键名均配中文 → 未命中
- D11 语言后门：本回合产出文本已审，无开脱钩子 → 未命中
- D12 加载时机：加载发生在工作完成后的发送前 → 未命中
→ 全空
```

**反例（禁止）**：`闸门快照：D1–D12 全部未命中。` —— 用判定标签替代实际核对，与「全部通过」同源。

合格/命中两种实例见 [`examples/snapshot-pass.md`](examples/snapshot-pass.md) 与 [`examples/snapshot-hit.md`](examples/snapshot-hit.md)。

## 与 aicheck 的关系

同一套门禁，两种定位：

| | `d12`（本技能） | [`aicheck`](../aicheck/) |
|---|---|---|
| 定位 | 宿主无关的可移植版 | WorkBuddy 市场打包版 |
| 措辞 | 不绑定任何平台工具名 | 使用 `Skill` / `present_files` 等平台表述 |
| 附加物 | 无 | `_icon.png`、`_skillhub_meta.json`、可视化导读 HTML |
| 适用 | 多宿主混用、要进仓库共享 | WorkBuddy 内直接安装使用 |

两者内容同源，改一处应同步另一处。

## 已知代价

| 代价 | 说明 |
|---|---|
| 输出变长 | 每次交付多十二行；短答也被拉长 |
| 强制真加载 | 每次交付前多一次读文件或调接口 |
| D7 可能过硬 | 合规敏感场景（法务、财务口径）不宜「自行拍板」，此时应显式声明假设并标「待签」 |
| 不校验事实 | 只担保交付纪律；结论对不对要靠领域专项检查 |
| D5 需持续警觉 | 尾巴是最容易漏的地方，需要人机都盯 |

## 验证

本技能自身的交付也过门禁。仓库内的检查口径：

- 四宿主接线一致性：`references/hosts.md` 的三条自检（能找到 / 会执行 / 留证据）
- 文件完整性：`SKILL.md`、`README.md`、3 份 `references`、3 份 `examples`
- 快照格式：十二行不缺项、每行有核对内容
