# 环境与启动

两种项目类型，两条路径。先判定再动手，别混着试。

| 判据 | 路径 |
|---|---|
| 有 `pyproject.toml` / `package.json` / `go.mod` | Web / CLI：装依赖 → 起服务 → 探活 |
| 有 `.csproj` / `.sln`，target 带 `-windows`（WPF/WinForms） | 桌面：装 SDK → build → 跑探测工具 |
| 有 `docker-compose.yml` 且依赖重（数据库、GPU） | 优先 compose，别裸装 |
| 只有 README 说"跑起来"但没有任何依赖清单 | 先找 releases / Dockerfile，都没有就只做静态分析 |

## Web 路径

### 1 建环境

```bash
python -m venv .venv
```

**不要先删已有的 venv。** 沙箱对批量删除有阈值（实测 9 个文件也曾触发 SIGTERM），`pip install` 会覆盖已有包，直接装就行。

### 2 先验索引，再装依赖

```bash
# 25 秒验通不通：能下载一个小包就说明索引可用
timeout 25 .venv/Scripts/pip download six -d /tmp/t \
  -i https://pypi.tuna.tsinghua.edu.cn/simple --no-deps --timeout 8

# 通了再全量
.venv/Scripts/pip install -r requirements.txt \
  -i https://pypi.tuna.tsinghua.edu.cn/simple --timeout 60 --retries 3
```

为什么先验：默认 PyPI 索引不可达时，`pip install` 会安静地卡一小时零进展，日志里没有明显错误，很容易误判成"包太大"。

### 3 装完先检查实体，别看日志

```bash
ls .venv/Lib/site-packages | wc -l
for p in fastapi streamlit uvicorn openai; do
  ls .venv/Lib/site-packages | grep -qi "^$p" && echo "$p OK" || echo "$p MISSING"
done
```

`sitepackages` 只有 2 项就说明根本没装上，跟耗时无关。

### 4 启动与探活

```bash
# 后台跑，别用管道截断（长任务带 | head 会收到 SIGTERM）
python main.py > /tmp/run.log 2>&1 &

# 探活：拿到 200 才算起来
curl -o /dev/null -s -w "%{http_code}\n" http://127.0.0.1:8080/docs
```

端口冲突就换端口，别反复重启。日志里出现 `Address already in use` 说明上一次没退干净。

### 5 探活成功后的两件事

```bash
# 抓接口清单（后面的枚举要用）
curl -s http://127.0.0.1:8080/openapi.json -o openapi.json

# 截图
python scripts/shot_pages.py --api http://127.0.0.1:8080/docs --webui http://127.0.0.1:8501 -o shots/
```

## 桌面路径（.NET / WPF）

### 1 先看有没有 SDK

```powershell
dotnet --list-sdks
```

输出为空、但 `dotnet --list-runtimes` 有 `Microsoft.WindowsDesktop.App` → **只有运行时，build 不了**。这是最常见的卡点。

### 2 装 SDK 到项目内，别装全局

```powershell
Invoke-WebRequest https://dot.net/v1/dotnet-install.ps1 -OutFile dotnet-install.ps1
./dotnet-install.ps1 -Channel 10.0 -InstallDir <项目>/.dotnet -Architecture x64
```

版本要对上项目 target（`net10.0-windows` 就要 10.x SDK）。装完用绝对路径调用：

```powershell
<项目>/.dotnet/dotnet.exe build <解决方案>.sln -c Release
```

### 3 用项目自带的探测工具当证据源

`tools/` 下常有 console 工程（如 `tools/PresetProbe`），通常 `ProjectReference` 主项目，能直接调内部 API，stdout 就是真实运行证据。优先级：

1. 探测工具 stdout（最强，等于运行时行为采样）
2. `dotnet build` 成功输出（工程严谨性）
3. 对纯逻辑类写最小 harness，调用并打印返回值

### 4 无头环境起不了 GUI 怎么办

如实写，别伪造。文章对应章节标注：

> 运行时界面截图未获取：WPF 应用需要交互式桌面会话，当前为无头环境。

然后补齐三条替代证据。这是**可接受的交付**，因为读者拿到的是可复现的构建与探测结果；伪造的界面图才是不可接受的。

## 镜像与加速

| 场景 | 做法 |
|---|---|
| pip | `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| npm | `--registry https://registry.npmmirror.com` |
| git clone 502 | 走 codeload tarball：`https://codeload.github.com/<owner>/<repo>/tar.gz/refs/heads/main` |
| 浏览器内核 | playwright 库与本地浏览器 build 号不匹配时，`executable_path` 指向系统 Edge/Chrome |
| dotnet | 官方 `dotnet-install.ps1` 装到项目内 `.dotnet/` |

tarball 降级的代价：没有 `.git`，拿不到 commit 信息。文章里注明"快照来源：tarball"，版本号从 README / CHANGELOG 取。

## 启动失败排查顺序

1. **端口占了吗** —— `netstat -ano | findstr :8080`
2. **依赖真装上了吗** —— 数 `site-packages` 条目，别读日志
3. **配置项缺失吗** —— 有没有把 `config.example.toml` 复制成 `config.toml`
4. **工作目录对吗** —— 很多项目要求从仓库根目录启动（相对路径依赖）
5. **模型/素材要预下载吗** —— 首次运行会拉模型，慢不是挂了
6. **权限问题吗** —— 写 `storage/`、`output/` 需要目录可写

每次只改一个变量，改完重试一次。同时改三处，成功也不知道是哪处起的作用。
