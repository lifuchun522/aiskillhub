# 零 Key 验证

这一步价值最高：它要么证明「不付一分钱也能跑通」，要么暴露出项目真实的付费依赖边界。两种结果都是好结论。

---

## 三个条件

绝大多数 AI 类项目，卡住"必须付费"的地方只有三处。逐一找替代入口：

| 卡点 | 免费通道 | 判断依据 |
|---|---|---|
| 调用大模型写文案 | **可手填的输入框** —— 直接传现成文案与关键词 | 表单里有 `text_area` / `script` / `keywords` 字段 |
| 付费 TTS 配音 | **系统/免费 TTS**（如 Edge TTS）、本地模型 | 音色列表里有 `edge-*` / `local-*` 前缀 |
| 素材检索 API | **本地素材目录** | 素材来源有 `local` 选项，或配置项有本地路径 |

三个都找到，就能拼出一条全免费链路。

---

## 四步找法

### 1 从表单入手，找可手填的输入

LLM 的唯一作用是"生成文案和关键词"。如果表单允许直接填，LLM 就被绕过了。

```bash
grep -rn "video_script\|keywords\|prompt" app/ --include=*.py | head
```

找到字段后，在 UI 上填值而不是留空，就不会触发自动生成。

### 2 从枚举值入手，找免费 TTS

```bash
grep -rn "voice_name\|tts" app/services/*.py | head -30
```

音色列表里带 `edge-` 前缀的通常走系统 TTS，零成本。选一个完整可用的值：

```
zh-CN-XiaoxiaoNeural-Female
```

**必须完整**：缺省 `-Female` 后缀可能匹配不上，任务会直接失败。

### 3 从配置入手，找本地素材

```toml
video_source = "local"
```

如果 UI 上点不动这个选项，就改配置文件再重启（见 [截图取证](04-截图取证.md) 的绕行原则）。

素材要自己造：

```bash
ffmpeg -f lavfi -i "color=c=0x1a5f9c:s=1080x1920:d=5:r=30" \
       -c:v libx264 -pix_fmt yuv420p clip01.mp4
```

纯色竖屏 5 秒，够验证链路。注意：很多项目有**素材路径白名单**（防目录穿越），文件必须放进指定目录，参数只传文件名。

### 4 提交 → 轮询 → 取产物

```bash
# 提交
curl -X POST http://127.0.0.1:8080/api/v1/videos \
  -H "Content-Type: application/json" -d @payload.json

# 轮询
curl http://127.0.0.1:8080/api/v1/tasks/<task_id>

# 取产物
curl -o final-1.mp4 "http://127.0.0.1:8080/api/v1/download/<task_id>"
```

每一步的响应原文都要记进文章 —— 这是"真跑过"的最硬证据。

## 产物验证

拿到文件不算成功，要证明**内容真的合成了**。

```bash
# 时长、大小、流信息
ffprobe -v error -show_entries format=duration,size \
        -show_entries stream=codec_name,width,height final-1.mp4

# 抽一帧看画面（字幕是否烧进画面、素材是否真用了）
ffmpeg -ss 8 -i final-1.mp4 -frames:v 1 frame.png
```

抽帧图是最有说服力的证据：读者能直接看到成品长什么样。

---

## 失败也是素材

零 Key 跑不通时，别只写"没跑成功"。要记录：

| 记录项 | 说明 |
|---|---|
| `failed_stage` | 卡在哪个阶段（文案/素材/配音/字幕/合成） |
| 错误原文 | 完整报错，不摘要 |
| 根因 | 项目设计限制 / 参数格式 / 环境缺失 |
| 判定 | 这类问题读者会不会遇到 |

三类根因的归属不同：

| 根因 | 写在哪 |
|---|---|
| 路径白名单、枚举严格匹配、单任务串行 | **边界思考**（项目设计如此，不是 bug） |
| 依赖版本、镜像、端口、编码 | **踩坑表**（环境问题） |
| 参数格式、必填缺省、字段名拼错 | **踩坑表**（能靠文档解决） |

区分这两类很重要：把设计限制写进踩坑表，会让读者误以为项目有缺陷。

---

## 零 Key 验证的产出

合格的零 Key 章节包含：

1. **三个免 Key 条件**的表格（条件 / 取值 / 依据）
2. 提交与轮询的**命令原文**
3. 关键参数说明（为什么必须这么传）
4. **产物清单表**：文件名 / 大小 / 时长 / 分辨率
5. **抽帧图**：证明字幕与画面真的合成
6. 踩坑表（区分设计限制与环境问题）
7. 结论一句：这条链路可复现 / 有条件可复现 / 不可复现

最后一条是很多文章缺的 —— 读者需要一句明确判断，而不是自己从细节里推。

---

## 什么时候放弃

有些项目的核心链路**结构上就必须付费**（云渲染、托管 ASR、闭源模型）。这时：

- 不要硬造一个假链路
- 明确写「零 Key 不可行，卡点是 <具体环节>，最低成本方案是 <哪个 Key>」
- 转去验证其他免费能力（接口层、素材、字幕样式），把能验证的都验证了

"零 Key 不可行"本身就是一个高价值结论，比含糊地说"需要配置 Key"有用得多。
