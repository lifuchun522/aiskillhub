# FAQ

## 这套和"读 README 写篇文章"有什么区别

三条硬差异：

1. **数字实测** —— Provider 数来自 `len(REGISTRY)`，端点数来自 `openapi.json`，不是从文档抄
2. **真跑过** —— 有启动探活、有全链路请求响应、有产物抽帧
3. **可复现** —— 命令是原文，读者照着能跑出同样结果

只做 1 叫整理，1+2 叫评测，1+2+3 才是这套要的东西。

---

## 一定要跑起来吗？跑不起来能不能写

能写，但要如实标注。

跑不起来的三种情况与处置：

| 情况 | 处置 |
|---|---|
| 环境太重（GPU、数据库集群） | 只做静态分析，文章明确写"未本机运行，基于源码分析"，所有结论标源码位置 |
| 需要私有凭据 | 走 [Key 问题单](07-Key问题单.md)，能验证的免费能力全部验证 |
| 无头环境起不了 GUI（桌面应用） | 用 build 输出 + 探测工具 stdout 替代，明确写"界面截图未获取" |

不可接受的只有一种：**装作跑过**。

## 多久能做完一个项目

中型项目（几千行、单一服务）约 3–5 小时，分布见 [四阶段与三专题](01-四阶段与三专题.md) 的时间预算表。

容易超时的三处：装依赖（索引不通会发现很晚）、UI 交互（控件点不动）、零 Key 参数调试。前两处看 [踩坑总表](09-踩坑总表.md) 能省，第三处只能靠读源码里参数怎么被消费。

## 桌面应用没有 Web UI 也没有 openapi，三源枚举缺一源怎么办

源 2 换成**项目自带的探测工具或 `--help`**：

- `tools/` 下的 console 工程（常见 `PresetProbe` 这类）→ stdout 就是运行时能力采样
- CLI 项目 → `--help` 与全部子命令的 `--help`
- 都没有 → 用最小 harness 调内部纯逻辑类，打印返回值

三源的本质是"三个独立视角交叉"，不是"必须是 REST 接口"。

## 特性树一定要八域吗

八域是默认骨架，因为它覆盖「输入 → 加工 → 增强 → 产物 → 接口 → 工程」的完整链路。两个例外：

- **项目只做单一能力**（比如只用了一个域的库）→ 合并成 4–5 个域，别为了凑数把空域画上去
- **域内条目过多**（某域 20+ 条）→ 拆成两个域，或者把低频的收进 `<details>`

宁可少画一个域，也不要把"这域没内容"暴露在导图上。

## 零 Key 跑不通，文章还有价值吗

有，而且可能更有价值。**"必须付费"是重要的采购信息。**

关键是把结论写清：

> 零 Key 不可行，卡点在 <具体环节>。最低成本方案是 <哪个 Key，多少钱>。已验证的免费能力有：接口层、素材处理、字幕渲染。

比含糊地说"需要配置 API Key"有用得多。

## 图片必须内嵌吗，外链不行吗

交付物是**单文件 HTML**，要能双击离线打开、能在邮件/IM 里直接发。外链图会失效。

代价是文件大：9 章 + 15 图约 800 KB，可接受。超过 2 MB 是没压缩。

---

## 为什么导图不用图片而用内联 SVG

| 方案 | 缩放 | 改条目 | 单文件 |
|---|---|---|---|
| 截图/PNG | 糊 | 重画 | ✔ |
| 外链 SVG | 清晰 | 改文件 | ✘ |
| **内联 SVG** | 清晰 | 改 JSON 重跑脚本 | ✔ |

内联还多一个好处：可以用 CSS 控制（全屏放大只需要 `:checked ~` 几条规则，无需 JS）。

## 渲染自检一定要 playwright 吗

不是必须，但**必须有替代的等价验证**。最低要求：

1. 结构断言（doctype / `</html>` / section 数 / 无占位符）—— 纯 Python 就够
2. 图片可用性 —— 打开页面看 `naturalWidth`，或用 Pillow 校验内嵌 base64 能解码
3. 导图交互 —— 这个只能靠浏览器，没有 playwright 就人工点一次开合

第 3 条不能省。历史上出现过"样式改完图没坏但放大失效"，纯结构断言完全测不出来。

## 内容清理到什么程度算够

一个自检问句：**把文章给一个没参与过程的人看，他会不会觉得作者在向他汇报工作？**

如果出现"我这次""本次实测""接下来我会"，就是在汇报。读者的视角里没有"你"，只有项目本身。

删完之后通常能省 10–20% 篇幅，信息量不变。

---

## 能用在非开源项目上吗

能用在这三类：

- 公司内部项目（源码可读）
- 有公开 demo 但源码闭源的产品（做特性探索与边界，跳过内核架构）
- 别人的技术方案（把"源码"换成"设计文档"）

不能用在纯黑盒产品上 —— 没有源码，学习段只能靠猜，违反第一条铁律。
