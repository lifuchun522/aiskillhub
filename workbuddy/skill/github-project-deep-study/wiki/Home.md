# GitHub 项目深度学习

把一个开源项目真正做到「能讲给别人听」：**结构化的理解** + **可复现的证据** + **一份能直接发出去的单文件 HTML**。

| 你的处境 | 该做什么 |

## 四段骨架

```
熟悉  →  它是什么 / 给谁用 / 为什么存在
学习  →  它怎么做到的（C4 + 核心抽象 + 关键路径 + ADR）
实战  →  真能跑吗（命令原文 + 实图 + 踩坑表）
特性探索 → 有哪些能力、哪些不花钱能跑（八域导图 + 矩阵 + 零 Key）
```

三专题横切全程：应用场景（5W1H）· 边界思考（六维）· 内核架构（一句话 + 链路图）。

为什么这么切、每段的合格判据 → [四阶段与三专题](01-四阶段与三专题.md)

## 八步流程

| 步 | 动作 | 产出 | 常见耗时 |
|---|---|---|---|
| 1 | 克隆 + 三源枚举 | `expected-enum.md`：模块 / 注册表 / 路由 / UI 入口 | 5–15 min |
| 2 | 装依赖、启动、探活 | 服务真跑起来的证据（HTTP 200 / 探测工具 stdout） | 10–60 min |
| 3 | 截图取证 | 面板实图 + 按操作顺序的流程实拍 | 10–30 min |
| 4 | 特性树八域 + 导图 | `mindmap.svg`（1800×N，矢量） | 10 min |
| 5 | 零 Key 验证 | 全链路跑通的请求/响应原文 + 产物抽帧 | 15–45 min |
| 6 | Key 问题单 | T0–T4 分档清单 | 10 min |
| 7 | 拼 HTML | 单文件（图片内嵌、PPT 卡片） | 15 min |
| 8 | 自检 | 结构断言 + 渲染断言 + 导图开合 | 5 min |

装依赖这一步最容易失控：一定要先验索引通不通，别等一小时才发现源不通 → [踩坑总表](09-踩坑总表.md)

## 五分钟上手

```bash
cd github-project-deep-study

# 1 枚举
python scripts/enum_features.py examples/demo-repo --depth 3

# 2 导图
python scripts/gen_mindmap.py --data examples/mindmap.sample.json --out mindmap.svg

# 3 拼 HTML
cp examples/article.main.html out.html
python scripts/build_article.py --main out.html \
  --fragment examples/article.section.html \
  --anchor '  <section id="s6">' --image IMG_A=examples/assets/demo-shot.png

# 4 打开 out.html 看效果
```

## 五条铁律

1. **不转述 README** —— 每条结论必须有源码 / UI / 接口三源之一佐证
2. **数字必须实测** —— 数量类从模块导入或接口取，禁止 grep 手数
3. **截图不伪造** —— 跑不通就写"未获取"并说明原因，不画示意图冒充
4. **区分两类问题** —— "项目设计如此"进边界思考，"环境问题"进踩坑表
5. **交付前实测** —— 结构断言 + 渲染断言 + 导图开合，目测不算验
