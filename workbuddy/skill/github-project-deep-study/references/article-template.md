# 文章骨架模板

复制下面的片段填空。每个 `<>` 都是必填位，写不出内容说明这一段还没真搞懂。

## 顶部

```html
<header class="hero">
  <h1><项目名> 学习笔记</h1>
  <p><一句话主题：它把什么变成什么></p>
  <p class="lead">按「熟悉 → 学习 → 实战 → 特性探索」结构撰写 · 含本地实战证据</p>
  <div class="meta">
    <span class="chip">仓库 <owner/repo></span>
    <span class="chip">技术栈 <A + B></span>
    <span class="chip">本地跑通 ✔ 实图</span>
    <span class="chip">零 API Key 出片 ✔</span>   <!-- 做到才写 -->
  </div>
</header>
```

## §0 元信息

| 项 | 值 |
|---|---|
| 仓库 | `owner/repo` |
| 本地路径 | `<绝对路径>` |
| 本次提交 | `<commit 前 7 位>` · `<日期>` · `<commit message>` |
| 学习步骤 | clone → 读架构 → 装依赖 → 启动截图 → 跑通 → 写笔记 |

## §1 熟悉（外围层）

1. **电梯演讲**：一句话说清「它是什么 + 把 X 变成 Y + 给谁用」。
2. **5W1H 表**：Who / What / Why / When-Where / How 五行。
3. **生态与边界初判**：周边有哪些依赖服务；官方声明的不适用场景。

## §2 学习（内核层）

1. **C4 四层表**：Context / Container / Component / Code，每层写清构成。
2. **核心抽象**：用第一性原理解释——剥离实现后它本质是什么（如"串行阶段流水线 + 可插拔注册表"）。
3. **关键路径**：画阶段图 / 数据流，**标出每个阶段的函数名与文件行号**。
4. **ADR 权衡表**：决策 / 背景 / 后果（正负都写）。

## §3 实战（验证层）

1. 克隆命令 + commit 输出原文
2. 环境搭建命令（含镜像等关键参数）
3. 启动命令 + 端口 + 探活结果
4. **实图 1**：目录结构或文件树（由脚本遍历真实目录生成）
5. **实图 2**：界面首屏
6. 踩坑表：现象 / 根因 / 处置

## §4 特性探索

1. **特性树**（八域）：A 文案/LLM · B 配音/TTS · C 素材 · D 字幕 · E 背景音乐 · F 合成/产物 · G 接口层 · H 工程特性
   - 每域标出「免费通道」与「需 Key 通道」
2. **特性矩阵表**：特性域 / 能力 / 需要外部 Key / 本次实测结果
3. **用户视角逐步操作**：编号 / 我要做什么 / 怎么操作 / 实测结果
4. **实图 3~6**：按域截取的关键面板（每个配 `<h4>` 小标题 + 图注）
5. **接口清单表**：分组 / 端点 / 用途（从 `/openapi.json` 抓，不抄文档）
6. **零 Key 全流程**（若跑通）：
   - 关键参数说明 + 三个免 Key 条件
   - 提交/轮询命令原文
   - 踩坑表（区分"项目设计"与"环境问题"）
   - 产物清单表：文件 / 大小 / 说明
   - **实图**：成品抽帧（证明字幕/画面真的合成进去了）
7. **特性探索结论**：稳 / 有坑 / 边界 三段

## §5 三专题

1. **应用场景整理**：核心场景 / 边缘场景 / 反例场景 / 痛点→方案映射
2. **边界思考**（六维表）：适用 / 不适用 / 性能 / 成本一致性 / 运维 / vs 同类
3. **内核架构**：一句话总结 + 链路图

## §6 费曼自测

三句话：它是什么 / 为什么快或慢 / 什么场景别用。
讲不清 → 回 §2 补架构与关键路径。

## 页脚

```
<项目名> 学习笔记 v1 · 结构复用《GitHub 项目学习结构大纲模型》
本地实战：clone ✔ → 依赖安装 ✔（<耗时>）→ 启动 ✔ → <零 Key 出片 ✔> → 抽帧验证 ✔
```

---

## 写作硬规则

- 数字必须来自实测：尺寸、时长、文件大小、进度百分比、耗时
- 图注必须写清来源：哪个 URL / 哪条命令 / 哪个 commit
- 没跑通就写"未获取 + 原因"，不伪造、不画示意图代替截图
- 代码标识保留原文并附中文解释（如 `_run_pipeline`（流水线编排））
- 「项目设计如此」与「环境问题」分开写，前者进边界思考，后者进踩坑表
