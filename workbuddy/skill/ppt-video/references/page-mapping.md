# 页映射：PPT 的页就是讲解的骨架

## 一、总原则

**页序 = 讲解顺序，一页不跳、一页不多、一页不少。**

用户给的配套文章只提供「血肉」——例子、反例、数字、金句。文章的段落顺序**不是**讲解顺序。
文章里写「第一……第二……」，而 PPT 把它们放在两页，就分两页讲。

## 二、铁律：N 页 = N 个起点

页时间轴靠「每页从第几段开始」来切。所以：

```
页图张数 N  ==  --starts 的个数  ==  --pages 的值
```

少一个起点，从那一页往后**全部错位**（右边显示 P8 的图，字幕在讲 P9 的内容）；
多一个起点，会多出「一页只出现十几秒」的怪相。

**最容易犯的错**：讲稿里多写了一个「四类场景」「三个层次」这种并列小结，
就顺手在 `--starts` 里多切一个起点，把 15 张图分成了 16 段。
**并列小结不是新的一页，它属于它所依附的那张图。**

正确做法：
1. 先 `ls` 数清楚页图张数 N（或看 `prep_slides.py` 的输出）；
2. 再定 N 个起点；
3. 用 `--page-segs`（每页几段）而不是手写 `--starts`，脚本自己累加，少一页会当场报错。

## 三、每页讲多久

按页均分配，但**必须按内容重要性浮动**：

| 页面类型 | 占比 | 说明 |
|---|---|---|
| 封面 | 1 段（10~15 秒） | 只报标题 + 一句「这一讲讲什么」，别在封面讲内容 |
| 议程 / 目录 | 1~2 段 | 说明这一讲分几块，给听众地图 |
| 内容页（主体） | 2~5 段 | 每页 60~200 字，看图上信息量 |
| 框架 / 架构图页 | 3~5 段 | 这种页信息密度最高，值得多讲：分层、箭头、每层职责 |
| 案例页 | 2~4 段 | 讲「做了什么、为什么这么做、结果如何」 |
| Q&A / 谢谢 | 1~2 段 | 收束 + 一句记得住的话 |

内容页少于 40 字：说明这页只是过渡，可以接受；
但整片平均每页 < 40 字时，听众会觉得「翻页比说话快」，要和用户确认合并页面。

## 四、跨页内容怎么归属

三种情况，三种处理：

1. **一句话讲完的事，图在下一页** → 让这句话**等**下一页开始再讲。
   即把起点往后挪到那句话，而不是提前讲。
2. **总结/延伸内容，没有独立页** → 挂在它所依附的那一页**末尾**。
   （例：「数据驱动有四类场景」是讲完数据架构那页的延伸，不是新页。）
3. **一页要讲的东西太多** → 不要拆页，**拆卡**。左边换一张卡继续讲同一页的图。

## 五、一页里怎么切卡

页内按「结构关系」切，不按句子切：

- 旁白说「三个层次」→ 一张三层的卡；
- 先说 A 再说 B（对照）→ 一张 compare；
- 先讲背景、再讲做法、再讲结果 → 三张卡（flow / bullets / quote）。

⚠️ **一页里并列 N 条总结，就拆 N 张卡。**
把「本章总结三条」画成一张三行的卡，然后字幕在说第二条、左栏三行一起亮——
这是实战中最常发生的语义错配，也是唯一必须靠抽帧人眼才能发现的问题。

## 六、切完之后怎么验

三道关，缺一不可：

1. **`add_slides.py` 打印的「每页首段原文」**：逐行读，确认这一页首段讲的是这张图。
2. **`semantic_check.py`**：看「跨段」清单，逐条判断是不是并列结构。
3. **渲完抽帧**：每页抽 1 帧，同时读字幕和左栏，确认说的是同一件事。

抽帧时点不要按页的固定比例取（容易落在卡片入场动画里），
要在页内挑一张卡，取 `卡片start + min(6s, 卡长/2)`；
要核字幕位置，取 `props.lines` 里某一行的中点，否则会截到行间空隙。

## 七、真实事故（记住这个代价）

数字化第 2 章：15 张图，讲稿里把「数据驱动四类场景」当成了独立一页，
于是切出 16 个起点。结果从 P8 起整片错位一页，右边永远慢一页。
修法只能重渲后 20708 帧（30 分钟）再 trim+concat 拼回。

**同样的错，改之前 3 分钟能发现，改之后 30 分钟。**
