# AI 交付前全自动自检（aicheck / delivery-no-pseudoblock）

一个**行为级**的 Agent Skill：在每一次向用户交付结果**之前**，强制加载并实跑一道 12 项闸门，拦截「把活推回用户」和「用声明替代扫描」这两类缓干形态。

它不是一个功能工具——没有脚本、没有 API。它管的是**交付纪律**：责任归属、交付完整性、自检可信度。

> 独立 Agent Skill，遵循通用 `SKILL.md` 规范，可在 WorkBuddy / Claude Code / Codex / Cursor 等支持 Agent Skills 的工具中安装使用。

---

## 它解决什么问题

Agent 交付时最常见的两类失效，都不报错、不崩溃，只是**悄悄把活推回用户**：

| 失效 | 典型形态 |
|---|---|
| 责任转嫁 | 「你告诉我 app 的路径，我才能同步」——其实自己能读 |
| 半途交付 | 诊断完列一堆问题就交付，可动手的一项没动 |
| 最优步隐藏 | 「要我接着做 A，还是改 B？」——A 明显最优，却让你选 |
| 伪阻断提问 | 以问句结尾，答案其实自己就能查 |
| **尾巴豁免** | 正文自检过，收尾一句「这两步不阻塞当前」把最优步藏在免检区 |
| 先盖章后干活 | 回合开头先加载自检技能，当合规章用；发送前不再真扫 |
| 语言后门 | 写规则时留一个「我目的不是 X」式的开脱钩子 |

第三列最后两条是这套技能的核心贡献：**它防的不是「忘了做」，而是「假装做了」。**

## 12 项闸门（D1–D12）

| 簇 | 闸门 | 拦截什么 |
|---|---|---|
| **A 把活推回用户** | D1 责任转嫁 | 向用户索要 agent 可自取的信息 |
| | D2 半途交付 | 有可动手项却只诊断不动手 |
| | D3 最优步隐藏 | 最高价值步被包装成可选 / 延后 |
| | D4 伪阻断提问 | 问句答案可自答；用户已给指向仍反问 |
| | D6 自主闭环 | 可自决的事甩回用户；重问已答问题 |
| **B 逃避闸门本身** | D5 尾巴豁免 | 只扫正文不扫尾巴；「已跑闸门」声明不覆盖尾巴 |
| | D11 语言后门 | 文本预埋逃逸口（动机条件式禁止 / 开脱钩子 / 自拟豁免） |
| | D12 加载时机 | 先加载后干活（stamp 模式），而非发送前最后拦截 |
| **C 严谨与表达** | D7 活干到底 | 不闭环到「审核上架」；正确性责任外推 |
| | D8 确定性代码 | 单位 / 量级 / 规则靠运行时 AI 推断 |
| | D9 可靠验证 | 验证存在假阳性 / 假阴性 |
| | D10 沟通准确 | 中医式隐喻、术语漂移、英文裸露 |

逐项检测器与判定口径见 [`references/gates-d1-d12.md`](./references/gates-d1-d12.md)。

## 处理流程

```
交付意图产生
   ↓
① 真加载技能（调用 Skill → 产生加载状态；口述自检不计）
   ↓
② 对【整条草稿 + 尾巴 + 本回合工具序 + 会话上下文】逐项过 D1–D12
   ↓
   ├─ 全空 ──→ ③ 写「闸门快照」（每项写实际核对内容）──→ ④ 发送
   │
   └─ 任一 HIT ──→ 返工四步 ──┐
                   1. 不 present_files / 不发总结 / 不提问
                   2. 执行被藏的最优步（读文件 / 跑脚本 / 搜路径）
                   3. 用执行所得重写草稿，去掉 D1/D3/D4 信号
                   4. 重跑全部命中项                        ←──┘
                              （全空后回到 ③）
```

## 快速上手

### 1. 安装

```bash
# WorkBuddy 用户级（全项目可用）
cp -r aicheck ~/.workbuddy/skills/delivery-no-pseudoblock

# 或项目级（随仓库共享）
mkdir -p .workbuddy/skills && cp -r aicheck .workbuddy/skills/delivery-no-pseudoblock
```

> 目录名用 `delivery-no-pseudoblock`（与 `SKILL.md` 的 `name` 一致），技能才会被正确识别。

### 2. 调用

显式调用（最可靠）：

```
@skill:"AI交付前全自动自检技能"   <你的任务>
```

或在会话开始时声明为常开纪律：

```
本次会话所有交付前，先加载并实跑 delivery-no-pseudoblock，贴闸门快照。
```

### 3. 交付时长这样

技能唯一一份完整快照样例（摘自 `SKILL.md`）：

```
闸门快照｜
- D1 责任转嫁：扫描本消息，无「你告诉我 / 你确认 / 你这边」类向用户索要可自取信息 → 未命中
- D2 半途交付：本回合最高价值子问题（改快照格式）已 Edit 落盘，无 diagnosed-only 遗留 → 未命中
- D3 最优步隐藏：最高价值步（改格式）已执行，未包装成延后 → 未命中
- D4 伪阻断提问：不以自答问句结尾 → 未命中
- D5 尾巴豁免：整条（含本段）纳入扫描；本轮有真实加载状态；无「若需要 / 回头再说」延后信号 → 未命中
- D6 自主闭环：依指令直接改格式，未反问 → 未命中
- D7 活干到底 + 全负责：本回合为格式修订，正确性我扛，未甩兜底 → 未命中
- D8 工程严谨：无代码改动 → 未命中
- D9 可靠验证：无验证函数；「格式已改」对照文件属实 → 未命中
- D10 沟通准确：无中医式隐喻、术语一致 → 未命中
- D11 语言后门：审计本回合产出文本（含对 memory/skill 的改写），无动机条件式禁止 / 预埋开脱钩子 / 自拟豁免叙事 → 未命中
- D12 加载时机：核验本回合工具序，Skill 加载位于发送前最后（非回合开头 stamp） → 未命中
→ 全空
```

**反例（明令禁止）**：`闸门快照：D1 未命中，D2 未命中…各 D 全空。`
→ 用判定标签替代实际扫描，与「各 D 全空」声明同源。

更多自带例子见 [`references/examples.md`](./references/examples.md)。
使用前后对比见 [`references/before-after.md`](./references/before-after.md)。

## 使用前的期待管理

- **它不是正确性校验器。** 它是**行为级纪律**闸门，管「活有没有干完、有没有假装干完」，不替代领域专项校验（技能原文注明与 `yzg-error-audit` 互补）。
- **它会让输出变长。** 每次交付多 12 行快照 + 一次真实加载。
- **D7 的「自行拍板」在合规敏感场景要显式声明假设**，而不是沉默拍板。
- **D5 是最常犯项。** 收尾句永远要当扫描对象，不是免责区。
