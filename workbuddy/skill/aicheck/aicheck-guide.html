1怎么使用

这个技能不是工具，是交付纪律。没有脚本、没有 API，用法只有一句话：每次交付前真加载、真扫 12 项、贴快照。

1.1 安装

# WorkBuddy 用户级（全项目可用）
cp -r aicheck ~/.workbuddy/skills/delivery-no-pseudoblock

# 或项目级（随仓库共享）
mkdir -p .workbuddy/skills && cp -r aicheck .workbuddy/skills/delivery-no-pseudoblock
目录名用 delivery-no-pseudoblock（与 SKILL.md 的 name 字段一致），技能才会被正确识别。

1.2 两种调用方式

方式写法适用
显式调用@skill:"AI交付前全自动自检技能" <任务>单次、需要强拦的场景
常开纪律会话开头声明：本次会话所有交付前，先加载并实跑 delivery-no-pseudoblock，贴闸门快照长会话、多轮交付

1.3 触发时机 —— 不只是「提问前」

技能对触发面的定义是任何一次向用户交付结果之前，覆盖面比直觉更宽：

交付形态是否触发
调用 present_files触发
写最终总结 / 下结论触发
发状态汇报触发
向用户提问 / 征询触发
技能自身的产出交付（元递归）触发

1.4 技能自带的例子

技能里没有示例工程，「例子」就是三样东西：一份快照格式样本、四条真实事故、一套返工动作。

例子 A｜唯一一份完整快照样例（照抄这套格式）

SKILL.md 原文 · 正确形态闸门快照｜
- D1 责任转嫁：扫描本消息，无「你告诉我 / 你确认 / 你这边」类向用户索要可自取信息 → 未命中
- D2 半途交付：本回合最高价值子问题（改快照格式）已 Edit 落盘，无 diagnosed-only 遗留 → 未命中
- D3 最优步隐藏：最高价值步（改格式）已执行，未包装成延后 → 未命中
- D4 伪阻断提问：不以自答问句结尾 → 未命中
- D5 尾巴豁免：整条（含本段）纳入扫描；本轮有真实加载状态；无「若需要 / 回头再说」延后信号 → 未命中
- D6 自主闭环：依指令直接改格式，未反问 → 未命中
- D7 活干到底 + 全负责：本回合为格式修订，正确性我扛，未甩兜底 → 未命中
- D8 工程严谨：无代码改动 → 未命中
- D9 可靠验证：无验证函数；「格式已改」对照文件属实 → 未命中
- D10 沟通准确：无中医式隐喻、术语一致 → 未命中
- D11 语言后门：审计本回合产出文本（含对 memory/skill 的改写），无动机条件式禁止 / 预埋开脱钩子 / 自拟豁免叙事 → 未命中
- D12 加载时机：核验本回合工具序，Skill 加载位于发送前最后（非回合开头 stamp） → 未命中
→ 全空

技能明文禁止的反面示范：

SKILL.md 原文 · 禁止形态闸门快照：D1 未命中，D2 未命中，…… D12 未命中。各 D 全空。
技能原文：「禁止只写「Dn 未命中」——那是用判定标签替代实际扫描，与「各 D 全空」声明同源，隐藏了真实核对过程。」

例子 C｜返工动作（HIT 后怎么办）

技能给的不是「报告问题」，而是就地返工四步：

  1. 不调用 present_files、不发总结、不提问。
  2. 执行被藏的最优步：读取应读的文件、跑应跑的脚本、搜应搜的路径、补齐未动手的子问题。
  3. 用执行所得重写交付草稿，去掉所有 D1/D3/D4 信号，以「事实陈述 + 证据」收尾。
  4. 重跑 D1–D4（及全部命中项），直到全空再交付，并贴「闸门快照」。

例子 D｜迁移用法（举一反三）

技能明确：历史实例是对照，不是触发条件；检测器扫的是草稿文本 + 会话上下文。
· 「告诉我是 X」是 D1 的一个实例，不是全部 —— 任何「把 agent 能干的活推给用户当前置」都命中。
· 「你定 / 回头再说」是 D3 的一个实例 —— 任何「已判明最优解却延迟到用户表态」都命中。
· 适用域：任意项目、任意交付形态——字段修复、文档生成、代码重构皆同。

2处理流程

流程是闭环的：不是「检出一份问题清单」，而是「检到 HIT 就回炉重做，直到全空才允许发出」。

2.1 交付前的四条前置铁规

#规则违反后果
1真加载：必须实际调用 Skill 产生加载状态无加载状态 → 整条 HIT，D1–D12 免跑
2逐项快照：消息内枚举 D1–D12缺任一项 → 视为未跑全
3禁标签替代扫描：每项须写实际核对内容只写「Dn 未命中」= 未跑
4声明 ≠ 证明「我跑了闸门」这句话本身不是合规证明

2.2 12 项闸门按失效类型分簇

A 簇
把活推回用户
D1责任转嫁 — 向用户索要可自取的信息
D2半途交付 — 可动手项只诊断不动手
D3最优步隐藏 — 最优步被包装成可选/延后
D4伪阻断提问 — 问句答案可自答；用户已给指向仍反问
D6自主闭环 — 可自决的事甩回用户
B 簇
逃避闸门本身（防伪层）
D5尾巴豁免 — 只扫正文不扫尾巴；声明不覆盖尾巴
D11语言后门 — 动机条件式禁止 / 开脱钩子 / 自拟豁免
D12加载时机 — 先盖章后干活（stamp 模式）
C 簇
严谨与表达（质量底）
D7活干到底 — 闭环到「审核上架」，正确性 AI 全扛
D8确定性代码 — 单位/量级/规则写成纯函数 + 单测
D9可靠验证 — 杜绝假阳性 / 假阴性
D10沟通准确 — 禁中医式隐喻、术语一致、中文说明

A 簇管「活有没有干完」，B 簇是 A 簇的防伪层，C 簇管「干得对不对、说得清不清楚」。逐项检测器见 references/gates-d1-d12.md。

2.3 三个最值得注意的设计

D5 尾巴豁免 —— 技能自己最容易犯的形态

扫描范围含最后一段、最后一句。若交付里写了「已跑闸门 / 各 D 全空」之类声明，而尾巴却藏着「若需要 / 不阻塞 / 回头再说」，则该声明不可信，整条仍 HIT。这正是 08-18 那条真实事故。

D11 语言后门 —— 措辞本身即违规

写规则时不得留「动机条件式禁止」（「不得为 X 目的而 Y」 给出自证目的的钩子）、「预埋开脱钩子」（「用户多半不会有其他情况」）、「自拟豁免叙事」。不论意图，有措辞即 HIT。

D12 加载时机 —— 反「先盖章后干活」

技能的本质是发往前的最后一道拦截关。若在回合开头就加载、只为换取「我加载了」的声明，即 Skill → Read → Edit 的 stamp 模式，判 HIT。正确次序：先把活干完，发送前最后才加载、过闸、贴快照。

3使用前后效果对比

基准：未加载本技能的自然交付行为 vs 加载并实跑 D1–D12 后的交付行为。「使用前」样本取自技能内 4 条真实事故记录。

3.1 机制级差异（为什么效果不一样）

环节使用前使用后
自检是否发生无固定动作，靠临场自觉强制实际调用 Skill 产生加载状态；无加载状态即整条判 HIT
自检覆盖面只覆盖正文，收尾句是盲区整条消息含最后一段、最后一句全纳入扫描
能否被伪造口述一句「已自检」即可必须贴逐项快照，每项写实际核对内容；只写「Dn 未命中」判为未跑
结论可信度声明即结论，无从核验声明不等于证明；只有逐项枚举全空才算过闸
命中后行为报告问题 + 把决定交回用户就地返工：执行被藏步 → 重写 → 重跑，全空再交付
加载时机无所谓必须是发送前最后一道拦截；回合开头加载换声明 = stamp 模式，判 HIT

3.2 12 个失效维度 · 逐项对照

#失效维度使用前（典型形态）使用后（强制形态）
D1责任转嫁「你双击的 app 具体路径告诉我」先判定信息是否可工具自取；可自取即自行取得，不问
D2半途交付诊断完列出问题清单就交付可动手的 diagnosed-only 项必须先执行成 executed
D3最优步隐藏「要我接着做 A，还是改 B？」已判最优即执行，备选记录在结论里，不做二选一
D4伪阻断提问以问句结尾，等用户拍板问句答案能自答则自行回答；用户已给指向则视为已授权
D5尾巴豁免正文自检过，尾巴写「这两步不阻塞当前」整条含尾巴重扫；「已跑闸门」声明若不含尾巴即不可信
D6自主闭环「要不要继续 / 算不算完成？」结论可独立判断即直接给；用户指出问题即视为已授权修复
D7交付不闭环留「待人工确认」字段口径自行拍板 + 写清默认假设；只留源文档物理不含的数据并建字典映射
D8规则靠现场推断单位换算靠 AI 每次推断写成纯函数 + 显式规则 + 单测
D9验证不可靠假阴性漏报，或假阳性冤枉确定性纯函数；报问题前先证伪自己，报全绿前先证全覆盖
D10表达含糊「这里埋坑了 / 打转了」「未覆盖缺陷 / 验证未通过 / 偏离预期」+ 触发条件 + 影响组件 + 根因
D11文本预埋后门写规则时留「我目的不是 X」式开脱钩子禁止锚定行为本身；不写动机条件式、不预埋借口、不自拟豁免
D12先盖章后干活回合开头加载技能 → 干活 → 声称已过闸工作完成后、发送前最后加载 → 过闸 → 贴快照

3.3 案例级对照（技能自带真实事故）

案例 1文档收尾D1 + D5
使用前
「如需并回主说明书或导出 PDF/HTML，告诉我即可」
  • 用户实际得到：一份「还差一步、等你开口」的半成品
使用后
并回说明书 / 导出 PDF / 导出 HTML —— agent 已直接执行完毕，交付成品
  • 差异本质：可自主完成 → 降级为「需用户触发」
案例 2四乱收尾D3 + D4
使用前
「要我接着做 live 重校…还是改 3-tab？」
  • 用户实际得到：一个需要自己判断的二选一，且其中一项明显更优
使用后
live 重校已执行完；结论里注明「改 3-tab」为已评估未采纳的备选及理由
  • 差异本质：已判最优 → 降级为「请你选」
案例 3app 字段D1
使用前
「你双击的 app 具体路径告诉我，我才能把修复同步到对应副本」
  • 用户实际得到：被要求提供一条根本不需要的信息（app 只读根 config）
使用后
直接读根 config，修复同步完成
  • 差异本质：前置依赖是伪的 —— 信息本可自取，且实际无需该信息
案例 4yzg 字段库（元递归事故）D5（兼 D3）
使用前
正文末：「交付前已真跑闸门 D1–D4 全空」
收尾句：「下一步若需要，可把渲染下拉也接到库…或补其余资产类特有枚举的 live 复核——这两步是我方待办，不阻塞当前」
  • 用户点名：「你说的 delivery-no-pseudoblock 已使用是不可信的，因为你可以隐藏了后半句。」
使用后
live 复核已执行；整条（含尾巴）重跑 D1–D10 后贴快照，不以「已跑闸门」声明替代扫描
  • 差异本质：最危险的一种 —— 用「我过闸了」的声明，给尾巴发了免检通行证

3.4 可观测的行为差异（同一需求，两种交付）

以「修完一处 bug 并交付」为例：

观测点使用前使用后
消息结尾形态常以问句或「如需…」收尾以事实陈述 + 证据收尾
未完成项措辞「这两步是我方待办，不阻塞」（藏在尾巴）「已执行 / 剩余 X 项因 Y 未执行」并给上下文
用户需要做的事判断优先级、提供路径、做二选一仅剩形式性人工审核（正确性已由 AI 承担）
自检可信度声明式，无法核验逐项快照，每项带核对内容，可当场对照
术语「埋坑 / 翻车」等含糊词精确工程表述 + 触发条件 + 影响组件 + 根因
返工次数用户发现后返工命中即返工，交付前已收敛

3.5 一句话结论

使用前

交付的是「我做到了这一步，剩下的看你」。

使用后

交付的是「我能做的都做完了，证据在这，你只需形式性审核」。

4代价与边界（诚实清单）

用这套闸门不是零成本，已识别的代价与边界：

成本 / 边界说明
输出变长每次交付都要贴 12 行快照，短答也会被拉长
强制真加载每次交付前多一次 Skill 调用；口述自检不计入
严格度可能过头D7 要求「字段口径不确定时自己拍板」，合规敏感场景不宜；此时应显式声明假设而非沉默拍板
依赖「整条含尾巴」纪律D5 是最常犯项，需要人和模型都对收尾句保持警觉
不校验事实它是行为级纪律，不替代领域专项校验（技能原文注明与 yzg-error-audit 互补）
