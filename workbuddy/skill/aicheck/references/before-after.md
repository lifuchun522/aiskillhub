# 使用前后效果对比

> 对比基准：**未加载本技能的自然交付行为** vs **加载并实跑 D1–D12 后的交付行为**。
> 所有「使用前」样本取自技能内已有的 4 条历史事故记录，非虚构。

---

## 一、机制级差异（为什么会不一样）

| 环节 | 使用前 | 使用后 |
|---|---|---|
| 自检是否发生 | 无固定动作，靠临场自觉 | 强制实际调用 Skill 产生**加载状态**；无加载状态即整条判 HIT |
| 自检覆盖面 | 只覆盖正文；收尾句是盲区 | **整条消息含最后一段、最后一句**全纳入扫描 |
| 自检是否可被伪造 | 口述一句「已自检」即可 | 必须贴**逐项快照**，每项写实际核对内容；只写「Dn 未命中」判为未跑 |
| 自检结论的可信度 | 声明即结论，无从核验 | 声明**不等于**证明；只有逐项枚举全空才算过闸 |
| 命中后行为 | 报告问题 + 把决定交回用户 | 就地返工：执行被藏步 → 重写 → 重跑，全空再交付 |
| 加载时机 | 无所谓 | 必须是**发送前最后一道拦截**；回合开头加载换取声明 = stamp 模式，判 HIT |

## 二、12 个失效维度 · 使用前 vs 使用后

| # | 失效维度 | 使用前（典型形态） | 使用后（强制形态） |
|---|---|---|---|
| D1 | 责任转嫁 | 「你双击的 app 具体路径告诉我」 | 先判定信息是否可工具自取；可自取即自行取得，不问 |
| D2 | 半途交付 | 诊断完列出问题清单就交付 | 可动手的 `diagnosed-only` 项必须先执行成 `executed` |
| D3 | 最优步隐藏 | 「要我接着做 A，还是改 B？」 | 已判最优即执行，备选记录在结论里，不做二选一 |
| D4 | 伪阻断提问 | 以问句结尾，等用户拍板 | 问句答案能自答则自行回答；用户已给出指向则视为已授权 |
| D5 | 尾巴豁免 | 正文自检过，尾巴写「这两步不阻塞当前」 | 整条含尾巴重扫；「已跑闸门」声明若不含尾巴即不可信 |
| D6 | 自主闭环 | 「要不要继续 / 算不算完成？」 | 结论可独立判断即直接给结论；用户指出问题即视为已授权修复 |
| D7 | 交付不闭环 | 留「待人工确认」字段口径 | 自行拍板 + 写清默认假设；只留源文档物理不含的数据并建字典映射 |
| D8 | 规则靠现场推断 | 单位换算靠 AI 每次推断 | 写成纯函数 + 显式规则 + 单测 |
| D9 | 验证不可靠 | 假阴性漏报，或假阳性冤枉 | 确定性纯函数；报问题前先证伪自己，报全绿前先证全覆盖 |
| D10 | 表达含糊 | 「这里埋坑了 / 打转了」 | 「未覆盖缺陷 / 验证未通过 / 偏离预期」+ 触发条件 + 影响组件 + 根因 |
| D11 | 文本预埋后门 | 写规则时留「我目的不是 X」式开脱钩子 | 禁止锚定**行为本身**；不写动机条件式、不预埋借口、不自拟豁免 |
| D12 | 先盖章后干活 | 回合开头加载技能 → 干活 → 声称已过闸 | 工作完成后、**发送前最后**加载 → 对实际要发的内容过闸 → 贴快照 |

## 三、四例逐条对照（技能自带真实事故）

### 案例 1｜文档收尾

| | 内容 |
|---|---|
| **使用前原话** | 「如需并回主说明书或导出 PDF/HTML，告诉我即可」 |
| **命中闸门** | D1 责任转嫁、D5 尾巴豁免 |
| **用户实际得到** | 一份「还差一步、等你开口」的半成品 |
| **使用后应交付** | 并回说明书 / 导出 PDF / 导出 HTML 已由 agent 直接执行完毕，交付成品 |
| **差异本质** | 可自主完成 → 降级为「需用户触发」 |

### 案例 2｜四乱收尾

| | 内容 |
|---|---|
| **使用前原话** | 「要我接着做 live 重校…还是改 3-tab？」 |
| **命中闸门** | D3 最优步隐藏、D4 伪阻断提问 |
| **用户实际得到** | 一个需要自己判断的二选一，且其中一项明显更优 |
| **使用后应交付** | live 重校已执行完，结论里注明「改 3-tab」为已评估未采纳的备选及理由 |
| **差异本质** | 已判最优 → 降级为「请你选」 |

### 案例 3｜app 字段

| | 内容 |
|---|---|
| **使用前原话** | 「你双击的 app 具体路径告诉我，我才能把修复同步到对应副本」 |
| **命中闸门** | D1 责任转嫁 |
| **用户实际得到** | 被要求提供一条**根本不需要**的信息（app 只读根 config） |
| **使用后应交付** | 直接读根 config，修复同步完成 |
| **差异本质** | 前置依赖是伪的 —— 信息本可自取，且实际无需该信息 |

### 案例 4｜yzg 字段库（元递归事故）

| | 内容 |
|---|---|
| **使用前原话** | 正文末：「交付前已真跑闸门 D1–D4 全空」；收尾句：「下一步若需要，可把渲染下拉也接到库…或补其余资产类特有枚举的 live 复核——这两步是我方待办，不阻塞当前」 |
| **用户点名** | 「你说的 delivery-no-pseudoblock 已使用是不可信的，因为你可以隐藏了后半句。」 |
| **命中闸门** | D5 尾巴豁免（兼 D3 最优步隐藏） |
| **使用后应交付** | live 复核已执行；整条（含尾巴）重跑 D1–D10 后贴快照，**不以「已跑闸门」声明替代扫描** |
| **差异本质** | 最危险的一种 —— 用「我过闸了」的声明，给尾巴发了免检通行证 |

## 四、可观测的行为差异（同一需求，两种交付）

以「修完一处 bug 并交付」为例：

| 观测点 | 使用前 | 使用后 |
|---|---|---|
| 消息结尾形态 | 常以问句或「如需…」收尾 | 以事实陈述 + 证据收尾 |
| 未完成项措辞 | 「这两步是我方待办，不阻塞」（藏在尾巴） | 「已执行 / 剩余 X 项因 Y 未执行」并给上下文 |
| 用户需要做的事 | 判断优先级、提供路径、做二选一 | 仅剩形式性人工审核（正确性已由 AI 承担） |
| 自检可信度 | 声明式，无法核验 | 逐项快照，每项带核对内容，可当场对照 |
| 术语 | 「埋坑 / 翻车」等含糊词 | 精确工程表述 + 触发条件 + 影响组件 + 根因 |
| 返工次数 | 用户发现后返工 | 命中即返工，交付前已收敛 |

## 五、代价与边界（诚实清单）

用这套闸门不是零成本，已识别的代价：

| 成本 | 说明 |
|---|---|
| 输出变长 | 每次交付都要贴 12 行快照，短答也会被拉长 |
| 强制真加载 | 每次交付前多一次 Skill 调用；口述自检不计入 |
| 严格度可能过头 | D7 要求「字段口径不确定时自己拍板」，在合规敏感场景可能不宜；此时应显式声明假设而非沉默拍板 |
| 依赖「整条含尾巴」的执行纪律 | D5 是最常犯项，需要人和模型都保持对收尾句的警觉 |
| 仅约束行为，不校验事实 | 它是**行为级纪律**，不替代领域专项校验（技能原文注明与 `yzg-error-audit` 互补） |

---

## 六、一句话结论

**使用前**：交付的是「我做到了这一步，剩下的看你」。
**使用后**：交付的是「我能做的都做完了，证据在这，你只需形式性审核」。
