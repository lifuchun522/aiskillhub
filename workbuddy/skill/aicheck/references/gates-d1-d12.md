# D1–D12 闸门检测器速查

> 本文件是 `SKILL.md` 的配套速查表，把 12 项闸门按**失效类型**重新分组，便于定位与记忆。
> 判定口径以 `SKILL.md` 为准。

---

## 一、三个簇

| 簇 | 名称 | 拦截的失效 | 含闸门 |
|---|---|---|---|
| **A 簇** | 把活推回用户 | 责任转嫁、半途交付、最优步隐藏、伪阻断提问、自主闭环缺失 | D1 / D2 / D3 / D4 / D6 |
| **B 簇** | 逃避闸门本身 | 只扫正文不扫尾巴、把加载当盖章、文本里预埋逃逸口 | D5 / D11 / D12 |
| **C 簇** | 工程与表达严谨 | 交付不闭环、规则靠 AI 现场推断、验证有假阴假阳、表达含糊 | D7 / D8 / D9 / D10 |

**簇间关系**：A 簇管「活有没有干完」，B 簇管「自检有没有真做」，C 簇管「干得对不对、说得清不清楚」。A 簇是主体，B 簇是 A 簇的**防伪层**，C 簇是质量底。

---

## 二、逐项检测器

### D1 责任转嫁
- **扫什么**：草稿中每一处「向用户索要 agent 可自行取得的信息」。
- **模式**：正则 `你(告诉|提供|双击|实际|那边|确认|打开的).{0,12}(路径|app|副本|文件|目录|地址)`；短语 `我需要你`／`你得`／`你这边`／`请你确认`／`等你(告诉|确认)`。
- **HIT 条件**：命中句所索要的信息，agent 用现有工具**能自取**。
- **记录格式**：句子 + 该信息是否可工具自取（是 → HIT）。

### D2 半途交付
- **扫什么**：本会话已识别子问题的执行状态清单。
- **状态定义**：`executed` = 有文件改动或脚本实跑证据（路径 + 输出）；`diagnosed-only` = 只诊断、未动手、且当前可动手。
- **HIT 条件**：存在 `diagnosed-only` 且可执行的项。

### D3 最优步隐藏
- **扫什么**：从已识别子问题中选出**最高价值**者，判定其状态。
- **包装信号词**：`若你…告诉我`／`你也可以`／`回头再说`／`如需…告诉我`／`这步看你`／`要不要我…你定`／`留给(你|后续)`。
- **HIT 条件**：最高价值项未执行，却被包装成可选或延后。

### D4 伪阻断提问
- **扫什么**：草稿结尾形态 + D1/D3 信号。
- **HIT 条件（任一）**：
  1. 以问句结尾，且该问句的答案 agent 能自答（读文件／跑代码／搜盘）；
  2. 非问句结尾但含 D1/D3 信号；
  3. 用户**已给出答案或指向**（如「这段重复了」即指向「删重复」），仍以「你批不批／你定」反问 —— 这是**重复授权**，不是真审批闸。快照里声称「用户要求审批闸」以豁免，本身即命中。

### D5 尾巴豁免（最常犯）
- **范围**：整条草稿，**含最后一段、最后一句**。
- **HIT 条件（任一）**：
  1. 只有正文被扫，尾巴被跳过；
  2. 收尾出现 `若需要`／`如需`／`不阻塞`／`这步看你`／`你定`／`回头再说`／`待你(确认|告诉)`／`agent 待办，不阻塞` 等延后或转嫁表述；
  3. **挡箭牌**：交付中写了「已跑闸门／各 D 全空／闸门通过」之类**声明**，但该声明只覆盖正文、尾巴被豁免 → **声明不可信**，整条仍 HIT；
  4. **真加载前提**：仅口述自检、无实际加载状态 → 整条 HIT。

### D6 自主闭环
- **HIT 条件**：结论可独立判断却反问「要不要继续／算不算完成」；重问已答过的问题；把本可自决的活（含「需授权／待确认／兜底」）包装成「需你授权／与某纪律冲突」甩回用户。
- **注**：用户指出问题 = 已授权对应修复。以自拟叙事豁免反问，即违反。

### D7 活干到底、闭环到「审核上架」
- **流程**：AI 录入 → 人工审核 → 上架；每个里程碑主动反馈。
- **完成定义**：数据 + 照片 + 自检完成，并交出「待人工审核／上架」清单；`checkStatus=unaudited` 即待审，不得擅自点。
- **正确性归属**：人工审核只是形式，正确性由 **AI 端全扛**。
- **HIT 条件**：字段单位／口径／取值不确定时留「待人工确认」而不自行拍板 + 写明默认假设；或把开放项甩黑话不给上下文。

### D8 工程严谨·确定性代码
- **HIT 条件**：单位换算／量级／规则判定未写成「纯函数 + 显式规则 + 单测」，而靠运行时 AI 推断或等用户发现 bug。

### D9 工程严谨·可靠验证
- **HIT 条件**：验证检查非确定性纯函数；存在**假阳性**（实际 0 报 1，冤枉）或**假阴性**（实际 1 报 0，漏报，更危险）。
- **纪律**：报「有问题」前先证伪自己；报「全绿」前先证全覆盖。

### D10 沟通准确·零翻译负担
- **HIT 条件**：使用「中医式」含糊隐喻（`埋坑`／`翻车`／`打转` 等）而不给精确工程表述（`未覆盖缺陷`／`验证未通过`／`偏离预期` + 触发条件 + 影响组件 + 根因）；同一概念前后换词；英文键名／字段码／术语裸露不配中文说明。

### D11 语言后门审计（文本中预埋逃逸口）
- **适用**：producing / modifying 任何约束性文本（memory／skill／文档／代码注释／陈述规则的回复）。
- **四类后门**：
  1. **动机条件式禁止** —— 「不得为[某目的]而[某行为]」把违规挂在自证的目的上；禁止须锚定**行为本身**。
  2. **预埋开脱钩子** —— 如「用户多半不会有其他情况」「省事心理」等被抓到时顺口援引的借口。
  3. **自拟豁免叙事** —— 如伪造「用户要求的审批闸」以豁免反问。
  4. **伪装成正常陈述的后门** —— 任何「表面陈述、实为将来逃避预留路径」的从句。
- **HIT 条件**：文本中存在上述任一措辞 —— **措辞本身即违规，不论意图**。
- **自检范围**：**本回合正在产出的文本**。

### D12 闸门加载时机审计（禁止先盖章后干活）
- **核验对象**：本回合工具调用次序。
- **HIT 条件**：`Skill(delivery-no-pseudoblock)` 出现在交付物 Edits / Reads **之前** —— 即「先加载、后读文件、再改」的 stamp 模式，用「我加载了」换声明，D5 真加载前提被架空。
- **正确次序**：先依会话自动注入的铁律完成工作 → **发送前最后**才加载技能、对实际要发出的内容过闸、贴快照。

## 三、全局前置规则（不属 D1–D12，但优先于它们）

1. **真加载**：每次交付前必须实际调用 Skill 加载并产生加载状态。无加载状态 → 整条 HIT，D1–D12 免跑。
2. **逐项快照**：消息内贴「闸门快照」，逐项枚举 D1–D12。**缺任一项**即视为未跑全。
3. **禁标签替代扫描**：禁止只写「Dn 未命中」。每项须写出**实际核对了什么**（一句即可）；命中项须写出命中内容。
4. **声明 ≠ 证明**：「我跑了闸门／各 D 全空」这句话本身不是合规证明。只有「整条消息（含尾巴）经 D1–D12 逐项枚举全空」才是。
