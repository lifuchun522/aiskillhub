0. 能力边界与铁律

本 skill 解决的是你的真实场景：阿里云「免费个人测试证书」（3 个月有效期）到期后不能续费，只能重新申请 + 部署到 OSS 自定义域名 HTTPS。

模块性质说明
只读巡检层（原 v1.3.1）只读entry_probe / cert_probe / probe_report / bench_baseline，只诊断、不写
cert_rotate.py（v1.4.0 新增）写（需授权）plan / inspect / rotate 三子命令，写操作必须 --authorized
铁律（三层，缺一不可）：
  • 任何写操作（申请 / 部署 / 改 DNS）必须显式传 --authorized，否则只出操作单、不触云；
  • AK/SK 仅从环境变量 ALIYUN_ACCESS_KEY_ID / ALIYUN_ACCESS_KEY_SECRET 读取，绝不硬编码、绝不写盘到 Memory/仓库；
  • 证书内容默认仅在内存中传递，部署到 OSS，不落本地磁盘（除非你手动导出）。

2. 创建 RAM 子账号 AK（最小权限）

安全切勿使用主账号 AK，按最小权限创建子账号。
控制台入口
阿里云 RAM 控制台 → 用户 → 创建用户 → 勾选「编程访问」
授权策略
AliyunYundunCertFullAccess（证书服务写）+ AliyunOSSFullAccess（部署到 OSS）。只读核查可降为 AliyunYundunCertReadOnlyAccess + AliyunOSSReadOnlyAccess
可选（自动 DNS）
若要用 --auto-dns，再授权 AliyunDNSFullAccess
# 取得后，运行时通过环境变量注入（不要写进任何文件）
export ALIYUN_ACCESS_KEY_ID="LTAI5txxxxxxxxxxxx"
export ALIYUN_ACCESS_KEY_SECRET="xxxxxxxxxxxxxxxxxxxx"
# Windows PowerShell:
$env:ALIYUN_ACCESS_KEY_ID="LTAI5txxxxxxxxxxxx"
$env:ALIYUN_ACCESS_KEY_SECRET="xxxxxxxxxxxxxxxxxxxx"
用完后建议在 RAM 控制台「禁用」或「删除」该 AccessKey，降低泄露风险。本 skill 不在任何位置持久化你的密钥。

3. 填写配置文件 config.json

配置复制样例并填写，--config 默认读同目录 config.json 
# 复制样例
cp config.example.json config.json   # 或 Windows: copy config.example.json config.json
字段必填含义 / 取值
domain是要换证的 OSS 自定义域名，如 www.example.com
oss_bucket是已绑定该自定义域名的 OSS bucket 名
region否OSS 地域，如 cn-hangzhou；影响 oss2 V4 签名与 CAS region
oss_endpoint是OSS 访问域名，如 https://oss-cn-hangzhou.aliyuncs.com
validate_type否固定 DNS（免费证默认 DNS 验证）
product_code否免费证产品码 digicert-free-1-free（默认已填）
wait_seconds否轮询间隔秒数，默认 30
max_poll否最大轮询次数，默认 40（约 20 分钟上限）
所有字段也可用 CLI 临时覆盖：--domain / --oss-bucket / --region / --oss-endpoint。AK 不在配置文件里，只在环境变量。

是（环境变量）
写操作
无（只读 Query）
退出码
0 成功；2 缺 AK / 缺 domain / 缺 oss_bucket
# 预期输出（节选）
{
  "quota": {
    "product_code": "digicert-free-1-free",
    "total": 20, "used": 3, "remain": 17,   # 当年免费额度剩余

6. 子命令三：rotate（真正轮换）

命令端到端执行：申请免费证 → DNS 验证 → 轮询签发 → 下载 → 部署 OSS 
# 手动加 TXT（默认交互确认）：
ALIYUN_ACCESS_KEY_ID=xxx ALIYUN_ACCESS_KEY_SECRET=yyy \
  python3 scripts/cert_rotate.py rotate --config config.json --authorized

# 同账号 DNS 自动加 TXT（免去手动）：
  ... rotate --config config.json --authorized --auto-dns

# 非交互环境（脚本/CI，跳过回车确认）：
  ... rotate --config config.json --authorized --auto-dns --no-confirm-dns
需要 AK
是（环境变量）
需要授权
必须 --authorized，否则拒绝（退出码 2）
退出码
0 部署成功；2 拒绝/失败（见错误表）

执行顺序（代码内 6 步）

  1. check_free_quota — 只读查额度，remain<=0 直接抛错终止。
  2. apply_free_cert — 调 CreateCertificateForPackageRequest，消耗 1 张免费额度，返回 OrderId。
  3. dns_validate — 调 DescribeCertificateState：
    • 返回含 record_value → 待验证，打印 TXT 主机记录/类型/值；
    • --auto-dns 时调 AliDNS 自动加 TXT；否则等你手动加后回车继续（--no-confirm-dns 跳过）。
  4. poll_status — 每 wait_seconds 秒轮询，最多 max_poll 次；当回包含 certificate+private_key 判定为 issued。
  5. download_cert — 用签发回包里的证书+私钥（默认仅内存，不落盘）；缺失则再查一次，仍无则报错提示手动下载。
  6. deploy_oss — 调 put_bucket_cname 覆盖部署到 OSS 自定义域名（force=True）。
# 成功输出（节选）
{
  "order_id": "123456",
  "domain": "www.example.com",
  "status": "deployed",
  "cert_not_after": "2612..."   # 从证书粗略抽取的有效期截止
}
完成后去 OSS 控制台「自定义域名 / 传输管理 / HTTPS」确认证书已更新，或在浏览器访问该域名看锁标。

9. 重要警告（务必先读）

  • 免费证只有 3 个月：每 3 个月这套流程要重跑一次，每次消耗 1/20 年额度。你正在做 CI/CD 自动化，建议把它做成定时任务（每 ~2 个月自动 rotate）。
  • 真实云链路仍为 NOT_VERIFIED：本手册步骤的端到端（rotate 真正申请+部署）需你的真实 AK 与 config 才能验证；当前仅 47 个离线单测（假客户端注入）全过 + plan/rotate 门控冒烟通过。
  • 覆盖即生效：deploy_oss 用 force=True，会直接覆盖 OSS 自定义域名上的旧证书，无回滚按钮——确保 domain/oss_bucket 填对。
  • DNS 验证窗口：手动加 TXT 后若未等生效就回车，轮询会超时失败；用 --auto-dns 可免去手动但需额外 AliDNS 权限。
