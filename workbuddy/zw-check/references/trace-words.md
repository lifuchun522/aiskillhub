# 加工痕迹词表

「加工痕迹」＝ 读者视角不该出现、但写作/交付过程会自然带出来的句子。
它不影响事实真假，只影响**这篇东西读起来像不像一篇文章**。

两级：

- `block`：必改。一律是「把交付动作写进了正文」或「把工程细节直接摊在读者面前」。
- `warn`：视文体斟酌。有些是口吻问题，有些在技术复盘里其实可以留。

规则表在 `scripts/zwcheck.py` 的 `TRACE_RULES`，本文件是它的人读版。

---

## block 级（必改）

| 类别 | 命中示例 | 为什么是痕迹 |
|---|---|---|
| 交付清单 | 本次实测还产出三类可复核文件 | 读者要读的是这件事，不是「我交付了哪些文件」 |
| 交付清单 | 原型可供二次开发，不包含云密钥 | 同上；范围声明属于附件说明，不属于正文 |
| 附件指向 | 完整文件和检查脚本放在文末附件里 | 把文章当交付说明写 |
| 附件指向 | 见文末附件 / 附件详见 … | 同上 |
| 文件路径外泄 | 对照结果页面在 `report/baseline-report.html` | 读者打不开本地相对路径；工程路径应在附件里说明 |
| 文件路径外泄 | `references/cloudq-integration-test.md` … | 同上 |
| 敏感串 | `atomdemo.xxx.cloud` | 未脱敏的内部域名/主机名 |

## warn 级（人工确认）

| 类别 | 命中示例 | 处理建议 |
|---|---|---|
| 自证腔 | 每一条我都不写「通过」，只写状态…不拿关键词当成绩 | 直接给结论和理由，别向读者自证没造假 |
| 自证腔 | 文章里也不会把它写成成功案例 | 同上 |
| 写作元信息 | 本文工程设计…不是引自标准原文的条款 | 事实边界要留，但可以叙述化，不必自称「本文」 |
| 写作元信息 | 征文要求用功能性、安全性… | 把「征文要求」这个外部约束写成中性陈述 |
| 宿主术语 | 在支持 Skill 的宿主里触发 | 读者不知道「宿主」指谁，落到具体工具名 |
| 过程口吻 | 本次实测 / 本轮检查 | 改成结果陈述（「实测输出如下」→「输出如下」） |

---

## 放行方法

```bash
# 逐条放行：把命中的原文串贴进 --allow（可重复）
python3 scripts/zwcheck.py text 稿件.md --allow '随原型一起提供'

# 只想看 block 级
python3 scripts/zwcheck.py text 稿件.md | grep -A99 '痕迹明细'
```

不提供「全部忽略」开关：放行必须逐条显式写出来，否则等于把闸门关掉。

---

## 真实命中例（清理前 vs 清理后）

同一篇稿件，清理前跑一次、清理后跑一次。清理前命中 11 条 block、10 条 warn：

```
[FAIL] 加工痕迹（block 级）为 0  命中 11 处
[WARN] 加工痕迹（warn 级）提示    命中 10 处
  [block] 交付清单｜本次实测还产出｜…本次实测还产出三类可复核文件：`operation-order…
  [block] 交付清单｜可供二次开发｜…效率对照页。原型可供二次开发，不包含云密钥和自动部署功能。…
  [block] 附件指向｜完整文件和检查脚本｜…完整文件和检查脚本放在文末附件里。…
  [block] 文件路径外泄｜`report/baseline-report.html`｜…对照结果页面在 `report/baseline-report.html`，它把…
  [block] 文件路径外泄｜`references/cloudq-integration-test.md`｜…完整的测试文档随 Skill 一起交付，放在…
```

清理后（删掉交付清单、把路径改成叙述性表述、把图注改成中性描述）：

```
[PASS] 加工痕迹（block 级）为 0  未命中
[PASS] 加工痕迹（warn 级）提示    未命中
```

改完后复跑必须 FAIL 归零，不能靠「我记得我改过了」。
