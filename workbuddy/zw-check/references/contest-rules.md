# 征文要求 ↔ 检查项映射

本文件把两场征文的硬性要求逐条落到 `scripts/zwcheck.py` 的检查项上，并标明**哪些判不了**。
要求原文来自征文页面，这里的表述是整理稿；以官方页面为准。

| 征文要求 | 检查项 | 判定方式 |

| 发布至同盟交流圈 `zone/tm` | C5 | NA：平台侧动作 |
| 打赛道专属 tag，**每篇仅一个** | C3 / C4 | PASS 条件：正文 `>` 标签行里的 `#标签` **token 数 ≤ 1**，且落在 `#AIOps最佳实践` / `#CloudQ共创征文` / `#Skill资产共创` 之内 |
| 三大模块任选其一写深写透 | — | NA：属选题判断 |
| 对标信通院《云上 Agent 基准度量模型》六维度 | C1 | PASS 条件：功能性、安全性、可靠性、成本效益、用户体验、性能效率 六词齐全 |

## 三、两类通用硬要求（不随赛道变）

| 要求 | 检查项 | 判定方式 |
|---|---|---|
| 字数上限（常见为 1000 字符，含空格） | T1 / N1 | PASS 条件：可见正文含空格字符数 ≤ `--max-chars` |
| 不能残留写作过程痕迹 | T2 / T3 | block 级必须为 0；warn 级人工确认 |
| 不用表格（编辑器易错乱） | H1 | PASS 条件：`<table>` 数为 0 |
| 去掉截图备注 | H2 | PASS 条件：`<figcaption>` 数为 0 |
| 图片走相对路径或内嵌，便于整包搬运 | H5 | PASS 条件：无外链 `src` |
| 正文里的源码事实与源码一致 | K1 / K2 / K3 | 目录树、元数据、单测数三项对齐 |

## 四、判不了的部分

以下项在稿件层无法自证，一律输出 `NA` 并附原因，不写 `PASS`：

1. 平台侧动作：发布板块、交流圈位置、成员资格、投稿时间线；
2. 账号侧事实：每人投稿篇数、原创性、是否刷量；
3. 人的判断：行文流畅性、可读性、案例专业性、创新性；
4. 缺输入：未提供 HTML 时的结构项与配图项；未加 `--run-tests` 时的单测实测项。
