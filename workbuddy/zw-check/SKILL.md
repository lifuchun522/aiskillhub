# zw-check · 征文稿件发布前检查

> 版本 1.0.0。把「发布前逐项核对」这件事从人肉目测变成可复算的检查：
> 每次交付稿件前跑一条命令，可疑点带上原文上下文直接列出来。
> 离线优先（仅标准库），可选浏览器实测图片。

## 什么时候用它

- 稿件要发到征文/频道/社区，需要逐条核对硬性要求（标题前缀、标签数量、字数上限、配图数量）；
- 被指出「内容太多了」，需要按 1000 字符之类的硬指标反复压字数；
- 担心正文里残留写作过程的痕迹（「本次实测还产出…」「完整文件放在文末附件」「report/xxx.html」）；
- 正文里嵌了技能目录树、`SKILL.md` 元数据、单测数量，需要与真实源码包对齐（评审最容易挑这里）；
- HTML 要粘进富文本编辑器，怕表格/图注/标签不配平导致样式错乱。

## 工具与证据边界

| 工具 | 作用 | 依赖 |
|---|---|---|
| `scripts/zwcheck.py` | 四类离线检查：`text` / `html` / `rules` / `consist`，可 `all` 一次跑完 | Python 3.9+ 标准库 |
| `scripts/check_images.py` | 用真实浏览器确认每张图真的加载出来（`naturalWidth > 0`） | 可选：`playwright` + `chromium` |
| `tests/test_zwcheck.py` | 51 项离线单测，全部纯函数 | 标准库 |

证据只来自两处：**稿件文本**与**技能源码目录**。

判不了的项一律标 `NA` 并写明原因，不猜：

- 发布板块、成员资格、截稿时间线 —— 平台侧动作，稿件无法自证；
- 「标点/行文风格是否通顺」—— 人的判断，不在机械检查范围；
- 未提供 HTML 时，配图数量与结构项无法判定。

## 执行步骤

1. **定口径**：确认赛道（`--track cloudq|workbuddy`）、字数上限（`--max-chars`）、配图下限/上限（`--min-images` / `--max-images`）。
2. **跑离线检查**：`python scripts/zwcheck.py all <doc> ...`，一次拿到字数、痕迹、结构、规则、一致性五组结果。
   - 若稿件是带工具栏外壳的预览页，用 `--from '<h1'` / `--to '<script>'` 划定正文区域，避免把工具栏文字算进字数。
3. **看 FAIL**：逐条修；`WARN` 级（宿主术语、自证腔、过程口吻）按文体斟酌，可用 `--allow '<原文串>'` 逐条放行。
4. **实测图片**（有配图时）：`python scripts/check_images.py <doc.html>`，确认「引用了」等于「真的能打开」。
5. **对齐源码**：带 `--skill-dir`（可加 `--run-tests`）核对目录树、`SKILL.md` 元数据、单测数量与正文声明是否一致。
6. **复跑**：改完必须重跑，直到 FAIL 为 0；`NA` 项按原因逐条说明谁去补。

## 安全检查项（四类，共 21 项）

| 类别 | 检查项 | 判定 |
|---|---|---|
| 文本 | 字数（含空格 / 不含空格 / 中文） | 超出 `--max-chars` → FAIL |
| 文本 | 加工痕迹 block 级（交付清单、附件指向、文件路径外泄、敏感串） | 命中 → FAIL |
| 文本 | 加工痕迹 warn 级（自证腔、写作元信息、宿主术语、过程口吻） | 命中 → WARN |
| HTML | `<table>` / `<figcaption>` 必须为 0 | 命中 → FAIL |
| HTML | 恰有 1 个 `<h1>`；`div`/`p` 标签配平 | 不满足 → FAIL |
| HTML | 图片全部相对路径或内嵌 Base64 | 有外链 → FAIL |
| HTML | 配图数量在 `--min-images` ~ `--max-images` 之间 | 越界 → FAIL |
| 规则 | 标题以「【征文】」开头（WorkBuddy 赛道） | 不满足 → FAIL |
| 规则 | 正文与 WorkBuddy 强相关（提及 ≥ 2 次） | 不满足 → FAIL |
| 规则 | 六维度齐全 + 三层口径齐全（CloudQ 赛道） | 缺项 → FAIL |
| 规则 | 赛道标签「每篇仅一个」，且落在官方候选集合内 | 越界或多标签 → FAIL |
| 规则 | `SKILL.md` 元数据仅 `name` + `description`；正文含工具/步骤/边界/铁律 | 不满足 → FAIL |
| 一致性 | 正文目录树与实际文件集合一致 | 有缺/有多 → FAIL |
| 一致性 | 正文内嵌元数据与 `SKILL.md` 逐字一致 | 不一致 → FAIL |
| 一致性 | 正文所述单测数与实跑一致（需 `--run-tests`） | 不一致或未通过 → FAIL |

## 安全边界

- **只读**：不修改稿件、不重命名、不写回文件；只向标准输出打印结果（`--json` 输出 JSON）。
- **不触网**：`zwcheck.py` 纯本地字符串/文件处理；`check_images.py` 只渲染 `file://` 本地页，不访问外部 URL。
- **不猜**：判不了标 `NA` 并写原因，不用「大概没问题」糊过去。
- **不改稿**：发现 FAIL 后由人或宿主决定怎么改；本技能不提供自动改稿。

## 铁律

1. **字数按可见正文算，图片与 alt 不计**；带页面外壳的预览页必须用 `--from/--to` 划区，否则工具栏文字会被算进字数。
2. **「引用了图片」不等于「图片能打开」**：有配图就必须跑一次浏览器实测，失败请求也要看。
3. **痕迹扫描是提示不是判决**：`block` 级必改；`warn` 级要人看——放行要显式 `--allow`，不能默认静默跳过。
4. **一致性只比 basename**：ASCII 目录树没写层级，`scripts/a.py` 与 `tests/a.py` 同名时会被判为同一项；命中 NA/歧义时以人核对为准。
5. **`--run-tests` 才会真的跑单测**：不加就是 `NA`，绝不拿「正文写了 36 项」当作「实测 36 项」。
6. **判不了的写 NA，不写 PASS**：NA 必须附一句「谁去补、怎么补」。
