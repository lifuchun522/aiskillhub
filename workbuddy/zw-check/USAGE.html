0 · 准备

安装 
# 整个目录拷到本机 skills 目录（按平台约定）
cp -r workbuddy/zw-check ~/.workbuddy/skills/zw-check

# 离线检查只要 Python 3.9+，无第三方依赖
python3 -m unittest discover -s tests -v      # 应输出：Ran 51 tests ... OK

# 图片实测是可选能力
pip install playwright && python -m playwright install chromium
本技能只读：不修改稿件、不改文件名、不写回磁盘；zwcheck.py 全程不触网。

1 · 先定口径

参数
赛道：--track cloudq | workbuddy | none（决定检查哪套征文规则）
字数上限：--max-chars 1000（含空格口径，最严）
配图区间：--min-images 3 --max-images 6
正文区域：--from '<h1' --to '<script>'（预览页带工具栏时必填，否则工具栏文字会被算进字数）
判定口径先定死的理由：同一篇稿子在不同口径下能差出几十字符。「含空格」是最严的一种，先按它定，别的口径只会更宽松。

2 · 一条命令跑完五组检查

all 
python3 scripts/zwcheck.py all 稿件.html \
    --track workbuddy --max-chars 1000 --min-images 3 --max-images 6 \
    --from '<h1' --to '<script>'

也可单跑一类：

python3 scripts/zwcheck.py text    稿件.md   --max-chars 1000
python3 scripts/zwcheck.py html    稿件.html --max-images 6
python3 scripts/zwcheck.py rules   稿件.md   --track cloudq --skill-md skill/SKILL.md
python3 scripts/zwcheck.py consist 稿件.md   --skill-dir skill/ --run-tests
退出码：0 全部通过 · 1 存在 FAIL · 2 参数或文件错误
JSON：加 --json 输出结构化结果，便于接自动化

3 · 结果怎么读

判读
状态含义动作
PASS该项通过无
FAIL硬指标不满足必改，改完复跑
WARN提示项（痕迹 warn 级）人看后决定；放行要 --allow '<原文串>' 逐条写
NA判不了，附原因看原因：平台侧 / 缺输入 / 人的判断，谁去补写在 detail 里
  [PASS] 字数（含空格）≤ 1000     含空格 960，不含空格 893，中文 561，余量 40
  [FAIL] 配图 ≥ 3 张             当前 0 张
  [WARN] 加工痕迹（warn 级）提示    命中 2 处，按文体斟酌
  [NA  ] 发布板块 =「实用文章」      平台侧动作，稿件无法自证
不给「全部忽略」开关：放行必须逐条显式写出，否则等于把闸门关掉。

4 · 图片要真的打开一次

check_images 
python3 scripts/check_images.py 稿件.html        # 人读输出
python3 scripts/check_images.py 稿件.html --json # 机器读输出

静态检查只能说「引用了 img/xx.png」，说不了「这张图真的加载出来了」。路径拼错、大小写不符、文件漏打包，静态检查全都看不出来，浏览器一看就现形。

== 图片实测（article.html）==
  加载成功 19/19
    [OK ] img/16-term-report.png  2360x1418
    [OK ] img/17-card-efficiency.png  2280x974
  失败请求：无
  结论：全部加载成功
失败请求也要看：requestfailed 非空同样判 FAIL，即使图片数对得上。

5 · 稿子里的源码事实要和源码对齐

consist 
python3 scripts/zwcheck.py consist 稿件.md --skill-dir skill/ --run-tests
检查项做法
目录树 vs 实际文件抓正文里的 ASCII 目录树代码块，与实际文件集合比对；只比 basename
内嵌元数据 vs SKILL.md正文里贴的 name/description 与真实 SKILL.md 逐字比
单测数 vs 实跑正文写「36 项」→ 真的跑一遍，比对 Ran N tests；不加 --run-tests 就是 NA
一致性比对必须用原始文本：目录树和元数据都在围栏代码块里，用去代码块的可见正文会全部漏检。CLI 已按原始文本比对。

6 · 改完复跑，接进 CI

复跑 
#!/usr/bin/env bash
set -e
python3 scripts/zwcheck.py all 稿件.html --track workbuddy --max-chars 1000 \
    --min-images 3 --max-images 6 --from '<h1' --to '<script>'
python3 scripts/check_images.py 稿件.html
echo "全部检查通过，可以发布"
门禁逻辑：FAIL 归零才算过。改完后复跑，不靠「我记得我改过了」。

已知边界

  • 不判行文流畅性、不判事实真伪、不判「像不像日记」——这些是人的判断，硬判会变成假阳性。
  • 平台侧动作（发布板块、成员资格、投稿篇数、时间线）一律 NA，只提示不判定。
  • 目录树比对只到 basename 粒度：scripts/a.py 与 tests/a.py 会被视作同一项，需人工确认。
  • 字数默认按可见正文计，图片与其 alt 文本不计入；带外壳的预览页必须用 --from/--to 划区。
  • check_images.py 依赖 playwright + chromium，未安装时返回 2 并提示安装命令。
  • 本技能不改稿：发现 FAIL 后怎么改由人或宿主决定。
