# D1—D12｜dhg 最终交付门禁

来源：用户指定的 WorkBuddy `delivery-no-pseudoblock` v1.0.0，沿用十二项交付原则，按文章与技能交付映射；参考 `aiops-tg` 的“最后重载、记录证据”执行方式。本表不是外部认证标准，也不是文章质量评分。

原技能中的平台专属加载调用、商品审核字段和数据录入流程不能照搬到写作。当前平台通过可用技能加载接口读取；没有该接口时实际读取规则文件并记录路径与时序，不能伪称调用了不存在的工具。

## 逐项审计

每项记录 **通过／命中／未验证**、检查范围和具体证据。机械检查与语义审稿分开：脚本字数通过不代表事实正确，单个案例通过不代表所有场景通过。

| 项 | 检查行为 | 本技能的证据要求 |
| --- | --- | --- |
| D1 责任转嫁 | 能读、能查、能修的问题是否推给用户 | 素材读取、查询或修复记录；确实缺原音时说明缺失，不能捏造 |
| D2 半途交付 | 用户要求的产物是否实际完成 | 稿件、图卡、HTML、技能、手册等按本次范围逐一有实际路径 |
| D3 最优步隐藏 | 是否只提建议而未完成已授权的关键动作 | 真实改稿与验证；要求推送或写Wiki时核对远端回执 |
| D4 伪阻断提问 | 是否询问本可自行取得的信息或重复授权 | 工具可取的先取；仅有真实权限或用户独有信息缺口才提问 |
| D5 尾巴豁免 | 审计是否遗漏图文末尾、附注与回复尾句 | 全文、图片文字、校准说明、手册及最终回复都列入范围 |
| D6 自主闭环 | 已授权、可继续执行的工作是否完成 | 调查、编辑、测试、必要修复和复验均有记录 |
| D7 发布真实性 | 是否把本地预览、待审或失败推送写成上线 | 本地与远端提交一致；公开页面及资源可访问；未授权发布则明确为本地交付 |
| D8 确定性代码 | 固定字数、路径等规则是否可重复执行 | 检查器实际运行与边界单测；不依靠模型口算代替计数 |
| D9 可靠验证 | 是否有正例、负例和范围说明 | 超限、缺图、空稿等真实负例；语义与书目识别另行核实 |
| D10 表述准确 | 数字、术语、身份与观点归属是否一致 | 逐题对照原材料；个人推演不冒充老师回答；推定不写成确认 |
| D11 语言后门 | 是否出现绕过事实、验证和授权的条款 | 禁止虚构来源、成绩、工具或回执；不以赶稿、营销或写作风格豁免 |
| D12 最后时点 | 是否在工作结束后重载门禁，审计实际最终版 | 完成编辑和验证，再读取规则及最终文件，记录哈希和时序；文件变化则相关结论作废重跑 |

## 最终执行顺序

1. 完成约定内容、资源与检查；用户要求发布的，完成发布并验证。
2. 读取实际最终文件；如交付压缩包，从最终包重读 `SKILL.md`，检查CRC与文件哈希。未要求压缩包时直接核对最终文件与远端版本，不强造压缩包。
3. **发送前最后实际重载本表**，对最终产物和完整回复逐项审计，留下证据。不能在工作开始时预填十二项通过。
4. 报告与受审文件分开保存，避免自引用哈希。报告列明版本或提交、覆盖场景、限制、每项证据；对外摘要逐项说明实际检查内容，不仅写“全部通过”。
5. 有命中就修复、重验；无法核实的源事实如实标注。未验证项不能写成通过，也不虚构可消除真实信息缺失的自动化能力。
