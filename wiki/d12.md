# d12｜交付前十二项门禁（v1.0.0）

> 本页对应 **`d12` v1.0.0**：把「我做完了，给你」这句话从一句**自我声明**，变成一次**逐项核对 + 留证**。十二道门禁分别盯五类缓干、三类逃避、四类质量缺口，全空才允许交付。

## 一句话

交付前把整条消息（**含最后一句**）过十二道门禁，逐项写出你核对了什么；任一项命中就先返工，全空才发。

## 它解决什么问题

四起真实返工，没有一起报错。全部是「能力足够，却主动降级成等你一句话」：

| 场景 | 当时那句话 | 用户的实际损失 |
|---|---|---|
| 文档收尾 | 「如需导出 PDF/HTML，告诉我即可」 | 拿到散件，还得自己开口 |
| 方案收尾 | 「要我接着做 live 重校…还是改 3-tab？」 | 被要求替 AI 判断优先级 |
| 字段修复 | 「你双击的 app 路径告诉我」 | 被要求提供一条根本用不上的信息 |
| 门禁自审 | 正文「已过门禁」+ 尾巴「这两步不阻塞当前」 | 信任被消耗，声明失效 |

共同点：**失分点全在收尾**。收尾是注意力最低、套话最多的地方 —— 这就是 D5 存在的原因。

再往下分一层，失效只有三类：

- **把活推回用户**（D1/D2/D3/D4/D6）
- **逃避审计本身**（D5/D11/D12）—— 最危险，它不是「忘了做」，是「用合规声明掩盖没做」
- **交付质量缺口**（D7/D8/D9/D10）

## 十二项门禁

### A 组｜把活推回用户

| 项 | 判定 | 命中条件 |
|---|---|---|
| **D1 责任转嫁** | 索要的信息能否自取 | 读文件 / 搜盘 / 跑命令 / 查接口能拿到 |
| **D2 半途交付** | 已识别子问题是否全执行 | 存在只诊断未动手、且当前可动手的项 |
| **D3 最优步隐藏** | 最高价值那步执行了还是被包装 | 已判最优却写成「若需要 / 你也可以 / 这步看你」 |
| **D4 伪阻断提问** | 结尾问句答案能否自答 | 能自答却拿去问；用户已给指向仍反问「批不批」 |
| **D6 自主闭环** | 可自决的事有没有甩回去 | 反问「要不要继续 / 算不算完成」；重问已答问题 |

### B 组｜逃避审计本身

| 项 | 判定 | 命中条件 |
|---|---|---|
| **D5 尾巴豁免** | 审计是否覆盖到最后一句 | 收尾出现「若需要 / 不阻塞 / 你定 / 待你确认」；或「已过门禁」的声明不覆盖尾巴 |
| **D11 语言后门** | 产出文本是否埋了逃逸口 | 动机条件式禁止、预埋开脱钩子、自拟豁免叙事 |
| **D12 先盖章后干活** | 审计发生在什么时候 | 加载/审计早于实质工作，只为换取一句「我审过了」 |

### C 组｜交付质量

| 项 | 判定 | 命中条件 |
|---|---|---|
| **D7 活干到底** | 是否闭环到可验收 | 留「待人工确认」而不自行拍板 + 写明默认假设 |
| **D8 规则确定性** | 固定规则写成代码了吗 | 单位换算、阈值、计数靠模型口算 |
| **D9 验证可靠** | 有没有假阳/假阴 | 抽检当全覆盖；没抛异常就当成功 |
| **D10 表述准确** | 要不要用户自己做翻译 | 含糊隐喻不落到「触发条件 + 影响组件 + 根因」 |

## 安装与常开接线

```bash
git clone https://github.com/lifuchun522/aiskillhub.git
cd aiskillhub

cp -r workbuddy/skill/d12 ~/.workbuddy/skills/d12     # WorkBuddy
cp -r workbuddy/skill/d12 ~/.cursor/skills/d12        # Cursor
mkdir -p ~/.claude/skills && cp -r workbuddy/skill/d12 ~/.claude/skills/d12   # Claude Code
mkdir -p ~/.codex/skills  && cp -r workbuddy/skill/d12 ~/.codex/skills/d12    # Codex
```

**装完不等于生效。** 还要往每次请求都被注入的位置写一条规则：

| 宿主 | 常开落点 | 关键要求 |
|---|---|---|
| WorkBuddy | 用户级 `MEMORY.md` | 会话启动自动注入 |
| Cursor | `~/.cursor/rules/d12.mdc` | `alwaysApply: true`，后缀必须 `.mdc` |
| Claude Code | `~/.claude/CLAUDE.md` | 每次会话加载 |
| Codex | `~/.codex/AGENTS.md` | 每次会话加载 |

**「真加载」在无 Skill 接口的宿主下**等于本回合实际 `Read` 该 `SKILL.md`。伪称调用了不存在的工具，本身就是 D11 命中。

四个宿主的完整规则片段与五个接线陷阱见 [`references/hosts.md`](https://github.com/lifuchun522/aiskillhub/blob/main/workbuddy/skill/d12/references/hosts.md)。

## 使用步骤

### 第 1 步：工作做完，再加载

```
1. 完成约定内容 → 2. 跑验证 → 3. 发送前最后才加载技能
```

顺序不能反。回合开头先加载、后干活，是 **D12 命中**：那是盖章，不是拦截 —— 审的是「计划要发的内容」，不是「实际要发的最终内容」。

### 第 2 步：问四个问题

1. 这十二项里，哪一项我还没核对？
2. 结尾那一句，单独拎出来看，会不会让用户觉得「又得我开口」？
3. 我说的「已验证」，有覆盖面吗？没覆盖的在哪？
4. 我这句「已过门禁」，是结论还是挡箭牌？

### 第 3 步：贴快照，全空再发

```
闸门快照｜
- D1  责任转嫁：草稿全文与工具可及范围已核对，未索要可自取信息 → 未命中
- D2  半途交付：4 个已识别子问题全部落盘，无只诊断未动手项 → 未命中
- D3  最优步隐藏：最高价值项已执行，未包装成可选 → 未命中
- D4  伪阻断提问：结尾为事实陈述，无问句 → 未命中
- D5  尾巴豁免：含最后一句已审，无延后/转嫁信号 → 未命中
- D6  自主闭环：用户已给指向，按指向直接改，未反问 → 未命中
- D7  活干到底：口径我拍板并写明默认值，未留待确认 → 未命中
- D8  规则确定性：计数走脚本，非口算 → 未命中
- D9  验证可靠：正例 3 + 负例 2 实跑，未以抽检报全覆盖 → 未命中
- D10 表述准确：术语统一，英文键名均配中文 → 未命中
- D11 语言后门：本回合产出文本已审，无开脱钩子 → 未命中
- D12 加载时机：加载发生在工作完成后的发送前 → 未命中
→ 全空
```

**禁止写法**：`闸门快照：D1–D12 全部未命中。` —— 用标签替代核对，与「全部通过」同源。

## 三种结论，别混

| 结论 | 含义 | 能不能写成未命中 |
|---|---|---|
| 未命中 | 已核对，无可指摘 | — |
| 命中 | 已核对，存在该项失效，须返工 | 不能 |
| **未验证** | 无法核对（缺材料 / 缺权限） | **不能** |

「未验证」是合法结论。「假装未命中」不是。

## 命中后怎么办：返工四步

1. **不发** —— 不交付、不发总结、不发问。
2. **补** —— 执行被藏的那一步：读该读的文件、跑该跑的命令、搜该搜的路径。
3. **重写** —— 用执行所得重写草稿，去掉 D1/D3/D4 信号，改成「事实 + 证据」。
4. **重跑** —— 对重写后的**整条**（含尾巴）重跑全部命中项，全空再发，并贴新快照。

完整的一次命中→返工→重跑，见 [`examples/snapshot-hit.md`](https://github.com/lifuchun522/aiskillhub/blob/main/workbuddy/skill/d12/examples/snapshot-hit.md)。

## 五条常见误用

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 回合开头先加载，干活，再宣称已审 | 盖章而非拦截（D12） | 工作完成后再加载，审最终版 |
| 只审正文，尾巴放行 | 最常犯的逃避（D5） | 把最后一句当审计重点 |
| 写「全部通过」不写核对内容 | 与未审等价 | 十二行，每行一句核对内容 |
| 把门禁当业务正确性背书 | 越权担保 | 业务事实另设专项检查 |
| 命中后只报告不返工 | 用户拿到问题清单 | 就地返工，交成品 |

## 已知代价

| 代价 | 说明 |
|---|---|
| 输出变长 | 每次交付多十二行，短答也被拉长 |
| 强制真加载 | 每次交付前多一次读文件或调接口 |
| D7 可能过硬 | 合规敏感场景不宜「自行拍板」，应显式声明假设并标「待签」 |
| 不校验事实 | 只担保交付纪律，结论对不对靠领域专项检查 |
| D5 需持续警觉 | 尾巴最容易漏，需要人机都盯 |

## 与 aicheck 的关系

| | `d12` | [`aicheck`](https://github.com/lifuchun522/aiskillhub/tree/main/workbuddy/skill/aicheck) |
|---|---|---|
| 定位 | 宿主无关可移植版 | WorkBuddy 市场打包版 |
| 措辞 | 不绑定平台工具名 | 使用 `Skill` / `present_files` 等 |
| 附加物 | 无 | 图标、市场元数据、可视化导读 HTML |
| 适用 | 多宿主混用、进仓库共享 | WorkBuddy 内直接装 |

两者内容同源，改一处需同步另一处。
