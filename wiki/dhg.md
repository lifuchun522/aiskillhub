# dhg 使用手册

`dhg` 将活动图片、录音转写、课件和亲历笔记整理为中文活动读后感或听后感。默认以老李的架构师、创业者视角写作，重点不是复述，而是回答“这件事对我的技术判断、产品取舍和下一步行动意味着什么”。

## 使用前准备

提供实际文件或可访问链接，说明活动背景、自己的身份、想保留的感受，以及是否需要HTML或发布。已有文章也可以直接修订。

- 图片与文字可单独提供；没有问答就写图文听后感，不虚构采访。
- 只有转写时做上下文校准，不能声称重新听过录音。
- 书名或片名不清时给出作者、情节、册数等线索；识别结果区分确认和推定。

## 调用示例

```text
使用 $dhg，读取这份活动Word和会后笔记，写一篇1500字以内的听后感。
我是架构师李福春，重点关注Agent的产品与创业机会。
每题保留“主持人问/听众问—老师答—老李思考”，
回答和思考各100字以内；思考先回答问题，再解释原因与我的行动。
圆桌照开篇，合照最后；补充会后交流，每点100字以内。
先交付本地Markdown和校准说明，不发布。
```

```text
使用 $dhg，修订现有文章，把新增的合作交流写成独立要点。
这次允许全文2000字，每段思考150字；保留老师回答的事实边界。
按现有wxwriter流程更新原HTML并发布，核对线上内容后给地址。
```

## 默认规则

| 项目 | 默认值或行为 |
| --- | --- |
| 篇幅 | 正文≤1500字，每段回答、思考、会后要点≤100字；用户最新要求优先 |
| 标签 | 老师答、老李思考；其他作者按指定称谓 |
| 思考 | 先给答案，递进解释，使用贴题生活类比，落到行动或验证 |
| 事实归属 | 原图、转写、用户会后经历、作者推演分开 |
| 缺项 | 不替嘉宾补全未回答的责任、时点、数据或保证 |
| 图片 | 讨论照开篇，合照收尾；剔除二维码、播放器和信息量低的图片 |
| 总结 | 客户为何买、如何交付、怎样复用；按需要补导图或行动卡片 |
| 发布 | 只有用户授权才发布；原工具的固定九章不覆盖本次用户要求 |

## 运行检查

在本技能目录执行：

```powershell
python scripts/check_article.py "D:/写作/活动听后感.md"
python scripts/check_article.py "D:/写作/活动听后感.md" --max-total 2000 --max-reflection 150
python scripts/check_article.py "D:/写作/张三听后感.md" --author-label 张三思考
python -m unittest discover -s tests -v
```

计数排除图片替代文本、链接地址和常规Markdown标记；保留正文、段落标签、标点、数字、英文字母，按非空白Unicode字符计数。编号要点及“会后／圆桌之后／交流感悟”二级标题内的粗体标签段落含小标题计数。脚本输出“需复核”不等于语义失败，也不等于语义已通过。

退出码：`0`表示所检机械规则无错误，`1`表示超限、缺图或空稿，`2`表示文件或输入参数错误。检测对象是常规内联链接、图片及约定标签；引用式链接、复杂HTML和非标准Markdown需人工核对。

## 验收与常见问题

- **脚本通过，为什么还审稿？** 字数与路径不能证明归属准确、因果成立、图中文字清晰或电影识别正确。必须回看素材。
- **为什么不固定九章？** 文章结构跟问题走；发布工具的默认模板不能制造重复章节。
- **只想改一处怎么办？** 保留现有有效内容与版本，仅修改授权范围，重新跑受影响的检查与末端门禁。
- **会不会自动发微信？** 不会。写作技能不自带账号或上传凭据；发布沿用环境已有工具和用户授权。
- **怎么证明真正上线？** Git推送核对提交号；网页发布再核对公开页面与图片，不能只给推测地址。

D12在全部编辑、检查和授权发布之后执行：重载规则，对实际最终文件和完整回复逐项登记证据；受审内容改动后相关结论作废并重跑。
